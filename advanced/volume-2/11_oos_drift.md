# 第二卷 · 11｜严格 OOS、漂移与模型增量检验

验证集上跑赢全场的模型，到了下一阶段就一定值得上实盘吗？

先问一个扎心的问题：**如果最后那六期测试结果你已经偷看过三遍、顺手微调了两次参数，那它还算“样本外（OOS）”吗？**

量化研究里最难防的漏洞，往往不是代码明目张胆写了 `shift(-1)`，而是**研究者自己的记忆**——看完测试期亏损后，“顺手”换个特征、改个正则强度、加一条止损线，再回头一看测试净值变漂亮了，便宣布模型通过了独立验证。更现实的是，就算你一丁点未来都没偷看，市场风格本身也会中途换剧本。

这一章要立住三件事：守住“先预测、后揭晓”的前推纪律；用配对检验诚实回答“新模型到底值不值得换掉旧基线”；以及把三种漂移拆开监控，别一亏钱就瞎改模型。

## 1. 时间切分只是起点：四个阶段各守各的规矩

写下一句 `train 2020–2022 / valid 2023 / test 2024` 谁都会，但真正决定证据含金量的，是你有没有守住每个阶段的红线：

| 阶段角色 | 允许做的事 | 绝不能越的线 |
|---|---|---|
| **探索训练** | 试想法、学参数、定缺失处理 | 偷用未来财报修订或今日成分股 |
| **开发验证** | 在事前登记的候选里选模型与超参 | 把挑出来的最高分当成未来预期业绩 |
| **冻结确认（OOS）** | 锁定全套规则，一次性运行并记录 | 看完结果再回头改参数，还嘴硬称未触碰 |
| **前瞻运行** | 决策时只用当时可知信息，事后评分 | 事后删掉失败版本或悄悄修改历史预测 |

记住：模型族、特征加工、初始训练窗、重训周期、风控和费用口径，**全都属于策略规则的一部分**。只要看了 OOS 结果再回头动了其中任何一项，原来的测试期就立刻降级成开发集，想重新确认只能等新的时间走出来。

### 1.1 为什么已公开的数据和“今日成分股”不能冒充最终 OOS？

第一卷和本卷反复算过的四股 18 期观察早已公开，适合核对算术，却永远不能再叫“未触碰测试集”。同样地，就算你抓了当前沪深 300 成分股从 2016 年回溯到 2025 年的日线，它也只能描述“今天依然留在指数里的公司在过去表现如何”——历史上被调出或退市的股票不在里面，因此第一步只能做覆盖率与缺失审计，不能直接当成无偏差的最终 OOS。

## 2. Prequential（前推验证）：先交卷，再看答案，再更新

在真实世界里，策略是一期一期往前走的。第 \(t\) 个信号时刻，模型只能使用**此时已经入库校验完毕的历史标签**：

\[
\mathcal D_t=\{(x_j,y_j):s_j<s_t,\ a_j<s_t\}.
\]

其中 \(s_j\) 是历史信号时刻，\(a_j\) 是标签真正可用的时刻（注意不是报价刚形成就可用）。每一期严格按单行道推进：

~~~text
当时可用的历史标签 -> 训练/更新当期模型 -> 输出当期预测
    -> 等待持有期结束与结果揭晓 -> 记分并归档
~~~

来看我们的 **REV20 课堂项目** 是怎么守住这条线的：在时段 `110` 冻结选型时，前面六个验证信号里，最后一条（时段 `105`）的标签要到时段 `111` 才揭晓，因此**只能用前五条（100 及之前）选出胜者**，把 `105` 坚决剔除；选定模型族之后，后六期（`110` 起）不再改换模型族，Ridge 仅按事先冻结的规则用新到达的历史标签滚动重训。

**重点区分**：按事前写死的规则定期滚动重训，是合法的前推；但看完后段成绩才拍脑袋说“2025 年该换另一个模型”，就是事后作弊。

**动手抓出偷看未来的模型：** 下面两条滚动曲线里，严格模型只用 `label_available < 当前信号` 的历史标签，错误模型只按信号日期更早筛选。调节窗口和标签延迟，看两者在后段关系反转时如何拉开差距。

## 3. 新模型真值得换掉简单基线吗？看清两道关卡

评判新模型能不能取代老基线，不要只盯一个汇总数字，先逐期配对求差：

\[
d_t = IC_{\mathrm{new},t} - IC_{\mathrm{baseline},t}.
\]

### 关卡一：全截面 RankIC 涨了，头部组合可能反而跌了

假设在同一批留出日期上，简单单因子平均 RankIC 是 `0.10`，复杂 Ridge 升到了 `0.12`；可一看实际只买前十只的 Top10 平均毛超额，单因子是 **+0.8%**，Ridge 却掉到了 **+0.4%**！

能不能只挑 RankIC 宣布 Ridge 胜出？绝对不行。RankIC 看的是整张几千只股票的大榜，而你真金白银只买了排最前面的十只——**头部的排序误差、风险暴露和换手代价，完全可能把整体排名的微弱进步吃得一干二净**。评价任务必须在训练前就冻死：如果你的目标是改进 TopK 实盘组合，就必须在同日期、同 \(K\)、同费率条件下直接做组合收益与回撤的配对对比；如果有限样本撑不起明确增量，老老实实留用简单基线。

### 关卡二：小样本配对检验与多重比较

拿到逐期差值 \(d_t\) 后，怎么判断正均值不是撞大运？举一个三期手算例子：三期差值为 `+0.03, +0.02, −0.01`，均值约 `+0.01333`（绝对和 `0.04`）。在独立对称零假设下，给这三个数任意翻正负号共有 \(2^3=8\) 种组合，其中足有 4 种的绝对和都不小于 `0.04`——双侧精确符号翻转诊断 \(p = 4/8 = 0.5\)，完全谈不上可靠增量。

而且即使五日标签不重叠，市场环境仍可能跨期相关。样本长了要用 HAC 或时间区块 Bootstrap；一口气做十几项对照时（例如 10 种模型对比基线 + 5 项删列消融共 15 项），还必须连同未定义的检验一起纳入 **Holm 校正**分母，绝不把试废的对照组藏进抽屉。

## 4. 策略开始亏钱了？把三种漂移和排查顺序分清楚

模型上线或走到后段表现变差，别急着一刀切重训。先把三种截然不同的“漂移”拆开体检：

| 漂移类型 | 发生了什么 | 常用观测工具 | 容易误判的点 |
|---|---|---|---|
| **特征分布漂移** | 因子均值、方差、覆盖率变了 | 分层均值、缺失率、PSI、KS | 输入分布变了，不代表预测一定失效 |
| **预测关系漂移** | 同一个因子变钝，甚至方向反转 | 滚动 IC、回归系数、分组单调 | 短期波动和真正结构断裂很难一眼分清 |
| **执行环境漂移** | 流动性萎缩、滑点变大、拒单增多 | 成交/拒单日志、冲击与容量 | 没做账本核对就容易误以为是因子失效 |

线上治理时，养成把日志分两本记的习惯：**决策前日志**（覆盖率、分布、数据延迟、模型版本、风控触发——只记当时已知事实）和**决策后日志**（标签、IC、净值、成本、拒单与复盘）。一旦出现回撤，按固定三步排查，顺序别乱：

1. **先对比毛收益与净收益**——是不是换手飙升或滑点变大把利润吃光了？
2. **再对比市场和行业基准**——是不是大盘风格、行业或市值 Beta 暴露惹的祸？
3. **最后才看中性化 IC 和分组**——排除成本和风格后，是不是选股信号本身钝化了？

在 **REV20 风险课堂项目** 里，我们配了一个事前冻结的透明监控规则做演示：每次决策只读已形成的最近六期 REV20 IC；若不足六期或覆盖低于 90% 标 `INSUFFICIENT`，若均值小于 0 标 `REVIEW`，两种情况都把目标资金预算砍半（例如 95% → 47.5%），其余情况保持 `NORMAL`。记住这只是教学规则演示——实盘里切忌只看两次反弹就草率宣布“因子恢复”并加回满仓。

## 5. 动手实验：用“篡改未来”的反事实测试抓泄漏

### 主实验：42 期前推推演与事后漂移诊断

运行 [advanced_model_validation_lab.py](../../examples/advanced_model_validation_lab.py)（42 个合成周度信号期 × 12 只证券：01–20 期开发训练、21–30 期验证六选一、31–42 期逐期用已可用标签重训并人为植入后段漂移）：

~~~bash
python examples/advanced_model_validation_lab.py --json
python -m unittest discover -s tests -p "test_advanced_model_validation_lab.py" -v
~~~

这套测试比“肉眼扫代码看有没有 `shift(-1)`”硬核得多，它做了两条**反事实断言**：
1. **把全部后段（31–42 期）收益彻底改写**，开发验证选出来的胜出模型必须纹丝不动；
2. **把当前期与未来期的标签彻底改写**，当期的预测打分和训练快照指纹必须纹丝不动（但下一期合法拿到更新后的历史标签重训时，预测才会随之变化）。

同时留意报告里的 `drift_diagnostic()` 显式标着 `posthoc`——它是**事后复盘工具**，绝不能倒灌进当期选型。

## 6. 练习与自检

1. 在后段测试期里看到 Ridge 表现比原选定的 `pairwise` 更好，于是换用 Ridge 并继续把这段测试期当作最终 OOS 汇报，行吗？
2. 事前冻结了“每周按当时已入库的历史标签滚动重训”，后段用到了上一周刚揭晓并校验完成的标签，这算未来泄漏吗？
3. 某因子的截面均值明显向上漂移，是不是一定意味着它的 RankIC 会崩塌？
4. 开发验证期算出了正的 IC 增量，能不能直接宣布多因子策略在真实市场稳定盈利？

<details>
<summary>展开核对答案</summary>

1. **答：不行。** 一旦后段结果反过来改变了模型选择，它就已经消耗成开发验证集，必须降级证据并另寻新的独立确认期。
2. **答：不算泄漏。** 前提是每条新标签的 `label_available_at` 严格早于本周信号，且重训规则事先冻结、版本完整留痕。
3. **答：不必然。** 特征分布漂移和“特征—收益预测关系漂移”是两回事，必须分开检验。
4. **答：不能。** 还需要独立样本外、时间依赖下的统计不确定性、交易成本与真实成交证据。

</details>

### 质量核对｜后段滚动重训时，哪条标签可以进训练集？

在教材封存的合成 PIT 事件里，当前信号时刻为 **2024-04-03 09:30**。手头有两条历史标签：第一条在 **2024-03-20 15:20** 已可用，第二条直到 **2024-04-03 15:15** 才可用。**问：按本卷 \(a_j < s_t\) 的门禁，哪条能参与本次重训？**

**答**：只能用第一条，**必须排除第二条**。哪怕回测脚本的内存里早就生成好了全部模拟未来收益，只要标签实际可用时刻晚于（或等于）当前信号时刻，就绝不能提前送进当期训练。
