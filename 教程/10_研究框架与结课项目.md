# 第 10 章：把一次实验变成可复现研究

本章第 1–9 节是现有机器学习示例的框架与结课要求。传统阶段先完成 [第 9a 章](09a_多因子合成与综合实训.md) 的三因子实训；本章第 10 节将 PDF 的研究框架职责映射到当前代码。两个阶段各自验收，不要求初级学习者先训练三种模型。

## 1. 六层职责

- 数据层：读取快照，生成特征、标签、股票池和可交易标记。
- 配置层：固定区间、标签、特征、切分、模型、组合和成本。
- 训练层：按时间切分，拟合预处理器和模型。
- 预测层：保存所有样本外预测。
- 回测层：把预测转成仓位、成交、成本和净值。
- 评价层：输出预测、组合、稳定性和暴露指标。

当前 `src/` 是教学版骨架，重点是职责清楚。生产系统还需要任务编排、缓存、数据版本、日志、异常恢复、权限、交易接口和风控。

## 2. 可复现性

一次实验至少保存：实验编号、代码版本、DuckDB 快照路径与时间、配置、特征版本、标签版本、随机种子、预测明细、回测明细和报告。只保存净值图无法审计。运行脚本默认创建 `outputs/.../<run_id>/`，并写入 `config_used.json`、`run_manifest.json`、`data_source.json`；设置 `QUANT_RUN_ID` 可使用有意义的实验编号。

## 3. 结课项目

题目：在同一真实样本和滚动切分下，比较 Ridge、Random Forest 和 LightGBM 对未来 5 日横截面收益排名的预测能力和 Top-N 组合表现。

必须包含：

1. 一个线性或非机器学习基线。
2. 三模型统一样本外预测。
3. 一个复杂度实验。
4. 五个随机种子的稳定性测试。
5. 一类特征的 Ablation。
6. 分年度评价。
7. 基础与压力成本。
8. 股票池/流动性变化测试。
9. 市值与行业暴露说明。
10. 失效阶段、局限和下一步。

## 4. 当前数据下的诚实结论边界

在补齐历史行业分类前，结课报告应写“横截面收益排名标签”，不能写“市场中性”或“行业中性标签”。若要使用财务特征，优先从 `qmt_fin_pit_event` 等按 `available_date` 组织的表取数，不要直接用报告期连接交易日。

## 5. 最终报告结构

执行摘要、假设与逻辑、数据与时点、标签与切分、特征与预处理、模型、样本外预测、组合与成本、稳健性与暴露、局限与下一步。评价标准是研究是否成立和能否复现，不是净值最高。

## 6. 一次实验的最小记录

建议每次只改一个主要变量，并在 `templates/experiment_log.csv` 或等价记录中写下：

```text
run_id:
parent_run_id:
research_question:
changed_variable:
old_value:
new_value:
hypothesis_before_test:
data_snapshot:
config_path:
expected_metric:
actual_metric:
decision: keep / reject / investigate
```

`run_id` 不是装饰。当前运行脚本会在 `outputs/demo/<run_id>/` 或 `outputs/duckdb_demo/<run_id>/` 保存样本、预测、回测、配置、环境和报告，避免新实验覆盖旧结果。若实验只留下“这次收益更高”的截图，就无法知道它用了什么数据、哪个成本、哪个随机种子。

## 7. 结课项目的分阶段流程

### 阶段 A：固定研究规格

先冻结 T 日、T+1 开盘、T+5 收盘、股票池、特征、切分、Top-N、成本和失败标准。不要在看到测试结果后改标签或缩短隔离期。

### 阶段 B：数据审计

输出日期覆盖、股票数量、重复键、缺失率、停牌/涨跌停比例和历史股票池变化。若行业或财务字段没有 PIT 版本，要把缺口写进报告而不是静默补齐。

### 阶段 C：基线和模型

先运行常数/等权因子/Ridge，再比较随机森林和 LightGBM。每个复杂模型都应有验证集选参记录，Test 只用于最终样本外结果。

### 阶段 D：稳健性

做一项复杂度实验、五个随机种子、一类特征 Ablation、分年度评价和基础/压力成本比较。每项实验都要说明是否在同一测试集上反复查看。

### 阶段 E：报告和答辩

回答“模型有没有排序能力”“能否在成本和成交约束下转为组合”“收益来自模型还是暴露”“如果失败，下一步修数据还是换模型”。不能只展示净值曲线。

## 8. 结课验收清单

- [ ] README 命令可以从干净环境启动，配置中的路径和参数真实生效。
- [ ] `sample.csv` 中每行的信号时点、标签起止和成交资格可追溯。
- [ ] 至少一折的 Train/Validation/Test 日期和参数选择可在 `metrics.json` 中复核。
- [ ] 测试预测没有参与标准化、调参、早停或特征筛选。
- [ ] 同时报告 RankIC、分组收益、成本后收益、基准、主动收益、回撤和分年度结果。
- [ ] 做过至少一项成本压力、特征消融和随机种子稳定性检查。
- [ ] 说明停牌、涨跌停、退市、新股、行业数据和财务 PIT 的限制。
- [ ] 报告能够被另一个人按 run_id、配置和数据快照复现。

## 9. 评分建议

可以用下面的比例自评，而不是用最终收益评分：

| 项目 | 权重 | 关键问题 |
|---|---:|---|
| 研究问题与时点 | 15% | 是否可执行、可证伪 |
| 数据和标签 | 20% | 是否 PIT、字段是否可审计 |
| 模型与验证 | 20% | 是否基线优先、选参不看测试 |
| 组合与成本 | 15% | 是否处理交易约束和基准 |
| 稳健性实验 | 15% | 是否做年度、消融、种子和压力成本 |
| 复现与报告 | 15% | 别人能否按记录重跑并理解限制 |

若收益很高但时点审计失败，项目仍不能通过；若收益一般但研究规格清楚、结果诚实、流程可复现，反而是合格的研究训练。

练习答案框架：先用六层职责画出数据流，再写一个 run_id 的文件清单；最后用验收表逐项打勾。任何“只在报告里声明、代码和输出中找不到证据”的项目，都只能算待补充项。

## 10. 传统因子框架与现有仓库的映射

PDF 第 18、20 页使用 DATA、UNIVERSE、FACTOR、OPERATOR、PREPROCESS、EVALUATE、COMBINE、PORTFOLIO、BACKTEST、REPORT 描述研究职责。这些是流程名称，不是本仓库已有的同名 API。

| 职责 | 当前代码/教材位置 | 传统项目还需补充 |
|---|---|---|
| DATA / UNIVERSE | `src/duckdb_data.py`、`src/synthetic_data.py`、第 02 章 | EP/ROE 字段、修订版本和严格历史状态审计 |
| FACTOR / OPERATOR | `src/dataset.py`、第 03a/03b 章 | 真实三因子实现、市场日历窗口和边界验证；没有通用表达式注册器 |
| PREPROCESS | 第 03b 章；`src/research.py` 的模型预处理 | 因子版本、每日清洗、暴露控制与审计输出 |
| EVALUATE | `src/metrics.py`、第 08a 章 | 原始覆盖报告、衰减与条件检验 |
| COMBINE / PORTFOLIO | 第 09a 章完整手算代码 | 月度分数、目标权重、缓冲、上限与未成交处理 |
| BACKTEST | `src/backtest.py` | 月度日历、逐日持仓现金、订单/成交、历史税费与公司行为 |
| REPORT | `src/research.py`、现有运行目录、研究模板 | 三因子对照、增量报告和完整交易审计 |

新增传统因子的实训顺序：写定义卡 → 在小数据上核对公式 → 接入 PIT 字段 → 生成逐日因子值和质量报告 → 复用评价函数 → 完成同口径对照 → 最后进入组合。此顺序是工程要求，不能把未实现的步骤写成已经运行的结果。

传统项目评分可按课堂练习 20%、模块作业 30%、结课项目 40%、研究记录 10%；模板见 [多因子结课报告](../templates/multifactor_project_report.md)。安慰剂、参数邻域、删除因子、1.5 倍/2 倍成本和延迟执行都应保留失败结果。第一阶段可以提交方法练习和项目设计；完整策略复现则必须提供实际账本与复现证据。
