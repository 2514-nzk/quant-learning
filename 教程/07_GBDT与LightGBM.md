# 第 13 章｜越改越好的训练分

随机森林没有让事情自动变简单。你又试了一种方法：先做一个预测，再让后面的树学习前面留下的误差。

如果每一轮都在修错，多加几轮会不会更好？这次，先看它在改什么。

## 1. 一次修正怎样发生

设 R01 的 A 真实排名标签为 1.00，当前预测为 0.60，差额为 0.40。若后面的树能给出这项修正，而本轮只加入它的 5%，新预测就是：

```text
0.60 + 0.05 × 0.40 = 0.62
```

0.05 帮助理解**学习率**。实际一棵树同时面对很多样本，学习的是分组里的误差，不能把这笔单样本算术当成实际模型某一轮的输出。

这种逐步修正的树方法叫 Boosting；LightGBM 是我们使用的实现。为了避免一下子追得太猛，每次修正可以小一点，也可以限制树本身的复杂度。

## 2. 把“再加一点”记成三行

你们固定了其他参数，只看增加树数后两张成绩单怎样变化：

| 树数 | 候选训练平均 RankIC | 候选验证平均 RankIC |
|---:|---:|---:|
| 15 | 0.5943 | 0.4381 |
| 50 | 0.6500 | 0.3800 |
| 150 | 0.7889 | 0.2200 |

这些值来自同一固定练习册的实际运行。训练那一列持续上升，验证那一列却下降。

你开始明白，“修正训练误差”里也可能包含对偶然波动的追逐。越来越熟悉做过的题，不等于更会回答后来那批题。

## 3. 谁负责喊停

你不想盯着测试表手动决定轮数，于是把停止工作交给验证集。

故事脚本最多允许 200 轮。如果验证损失连续 20 轮没有改善，就停止；这次记录到最佳轮数为 **14**。随后用相同轮数，在训练加验证数据上重训，再交最终测试。

```python
# 接口片段：验证输入和答案用于观察停止时机，测试集不在这里。
candidate.fit(
    x_train, y_train,
    eval_set=[(x_validation, y_validation)],
    callbacks=[early_stopping(20, verbose=False)],  # 连续 20 轮不改善就停止。
)
best_round = candidate.best_iteration_  # 保存选出的轮数，而不是靠记忆补写。
```

为什么 14 不必等于上表排序指标最好的那个候选？因为这次早停监控的是验证平方误差，表格展示的是验证 RankIC。一个在意数值误差，一个在意名次；指标职责要如实记录。

## 4. 小林没有给“更复杂”发奖状

你们现在保留了 Ridge、深度 4 的森林，以及按验证损失早停的 LightGBM。手工动量和三列等权仍然在比较名单里。

小林把这一页收好：“先别按验证分差一点点就写成胜负。最后那批题还没有参加选择。”

模型设置、早停轮数和数据切分都确定后，我们终于可以打开 R47–R60 的统一测试成绩。
