# 第二卷 · 14｜可复现研究工程与综合项目

> **状态：教学版 v1 方法与例题内部校审完成；合成组合→订单→资金→审计子流程可复算。** 本章不是完整真实 A 股 PIT 研究项目，也没有真实市场 OOS、成交或策略有效性证据。所有实验收益来自人工构造的价格。

## 核心问题：第三方能否独立核查研究中的每一步？

一份研究报告如果只有最终净值曲线，第三方不能知道：模型是否看过未来、是否用当前股票池回填历史、目标订单是否买得到、现金是否被重复使用，或者手续费有没有计入。

**计算可复现性**与**研究结论可信度**是不同层级：用同一错误数据跑出完全一致的收益，证明不了策略有效。真正专业的交付物应同时记录数据来源、研究协议、时点、模型选择、订单执行、异常日志及“允许失败”的判定。

## 1. 一份研究包的最低结构

~~~text
study/
  contract.json          # 假设、样本、时间门禁、失败条件
  data_manifest.json     # 来源、授权、历史版本、缺失和哈希
  features_and_labels/   # PIT、因子公式、标签结束与可用时刻
  validation/            # 开发期、确认期、模型版本和测试暴露历史
  portfolio_targets/     # 协方差、目标权重与全部约束
  order_ledger/          # 订单、实际成交、未成交、手续费与现金
  evidence/              # 不确定性、敏感性、反例和停止规则
  report.json            # 输入、配置、代码指纹与可复算摘要
  reproduce.md           # 环境、命令、版本及验收边界
~~~

研究日志应该保留失败和拒单；不能为了得到漂亮收益图而只留下成交成功记录。历史数据可能受许可约束，不能因为希望可复现就把有版权或受限的行情、交易账户记录提交到公开 GitHub。

## 2. 验收分为七道证据关卡

| 关卡 | 核心问题 | 失败时的处理 |
|---|---|---|
| G0 来源和权限 | 能否合法使用并重建历史数据？ | 不报告真实市场有效性 |
| G1 PIT 和标签 | 特征、行业、财务和标签是否遵守时点？ | 停止并审计泄漏 |
| G2 基线与选择 | 是否与冻结的简单基线公平对照？ | 降级为探索结果 |
| G3 严格 OOS | 是否有独立且充分的历史/前瞻证据？ | 明确证据不足 |
| G4 组合与风险 | 仓位、行业、现金、容量和换手是否满足？ | 记录偏差并降低风险 |
| G5 订单与净值 | 拒单、税费、实际仓位和 NAV 能否复核？ | 不发布净收益结论 |
| G6 部署与治理 | 风控、监控、告警、回滚与停机是否齐全？ | 仅限研究或纸面交易 |

本轮代码只能验证合成任务中部分 G1/G4/G5 的程序逻辑，不代表真实 PIT、风险系统或生产部署已被验收。“单元测试通过”不能代替金融研究的市场证据。

## 3. 项目指纹：不应只有一个 final.csv

本章的 [合成综合实验](../../examples/advanced_portfolio_execution_lab.py) 报告包括：

- `study_id` 与 `source_kind`，强制标明人工数据性质；
- `config_sha256`：研究配置按固定键排序的哈希；
- `input_sha256`：完整人工市场与信号数据指纹；
- `code_sha256`：实验入口文件内容的 SHA-256；
- `report_sha256`：整个报告（不含这个自身字段）的 SHA-256；
- 三个策略分支的决策、目标权重、订单事件、每日持仓、现金及费用；
- 单独重新核算的现金、NAV 和决策时间检查；
- 未覆盖的市场风险、订单排队和真实来源缺口清单。

相同输入、配置和代码应生成相同结果和指纹；变更配置时要保存新版本，而不是覆盖旧产物。**哈希可以发现数据改变，不能证明数据真实，更不是完备的来源签名或审计系统。**

## 4. 动手实验：交付一份可以重跑的合成报告

在仓库根目录执行：

~~~bash
python examples/advanced_portfolio_execution_lab.py
python examples/advanced_portfolio_execution_lab.py --json
python -m unittest discover -s tests -p "test_advanced_portfolio_execution_lab.py" -v
python examples/advanced_portfolio_execution_lab.py --output outputs/synthetic_portfolio_audit.json
~~~

最后一行仅在指定文件**不存在**时创建 JSON，程序拒绝覆盖已有结果。后续实验可更换版本文件名，保留之前的失败与对照数据。不要把真实受限行情或个人交易信息上传到公开仓库。

若需要回顾前置章节，可先独立运行：

~~~bash
python examples/advanced_protocol_pit_lab.py --json
python examples/advanced_factor_research_lab.py --json
python examples/advanced_model_validation_lab.py --json
~~~

它们分别负责：研究合同和 PIT 的方法、因子检验与统计推断、开发期模型选择和时间前推。**目前它们是独立的合成练习，还不是用统一真实 PIT 面板衔接的完整生产流水线。** 本章“端到端”只指本次人工信号到资金与对账的子流程。

## 5. 怎样独立复核，而不是只相信作者汇总？

至少完成以下检查：

1. 用订单 `notional`、佣金和卖出税费独立复算最终现金；
2. 用每日持仓股数、人工收盘价复算 NAV；
3. 修改未来一个交易日的数据，确认此前决策不改变；
4. 同日买入后尝试卖出，确认简化 T+1 拒单；
5. 对买入、卖出和停牌设置阻挡，确认拒单原因在账本留下；
6. 破坏一条现金或净值记录，确认审计测试失败；
7. 比较现金、等权和离散优化三个分支，且保证使用相同的执行成本；
8. 每个报告都标明只用于教学，不宣称真实 A 股业绩。

出现不一致时，第一目标是**保留复现条件并解释失败**，不是删除不利交易。

## 7. 习题与核对

**题 A：** 使用今天的存活股票池，代码跑出完全相同的净值，可以说严格 PIT 吗？

答：不能。可复现性不能修复历史证券缺失和后见修订。

**题 B：** 账本出现 1 元未解释差异，可以在最终报告里四舍五入隐藏吗？

答：不能。应确定金额精度与核算规则，找出差异来源，修复或明确停止条件。

**题 C：** 本章人工实验中优化分支超过等权，可以建议真实资金使用吗？

答：不能。所有收益由合成价格和简化执行产生，不能推断实际市场。
