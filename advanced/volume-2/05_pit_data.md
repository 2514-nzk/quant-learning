# 第二卷 · 05｜全市场 PIT 数据工程与动态股票池

> **状态：教学正文初稿；合成 as-of 连接与边界测试可复算。** 尚未接入完整 A 股历史财务、行业版本及退市数据。示例中的证券、数据和披露时间均为人工构造，不能据此判断策略有效性。

## 本章目标：今天的数据，不一定属于过去

即使程序完全没有读取“未来收益”，如果使用的是今天下载的股票清单、后来修订的财报和当前行业分类，回测依然可能有前视偏差和幸存者偏差。

完成本章后，应能设计版本化数据合同，恢复历史决策时点可用信息；分清历史上市资格、信号资格与订单成交资格；正确处理财务修订、行业版本、数据缺失及来源审计。

## 1. PIT 是关于“何时知道”的研究方法

Point-in-Time（PIT）的核心问题：**研究者在信号形成那一刻，真正能知道哪个版本的数据？**

| 字段 | 含义 | 不能替代它的字段 |
|---|---|---|
| effective_at / period_end | 数据对应的生效日期或财务报告期 | 公告日期 |
| source_published_at / known_at | 该版本最早有可靠公开证据的时刻 | 最近下载时刻 |
| ingested_at | 数据实际进入研究系统的时刻 | 证券交易日 |
| available_at | 采集、许可和校验完成后的可使用时刻 | 报表报告期 |
| snapshot_id / source_id | 数据来源、原始记录及快照版本 | 随手记下的文件名 |
| revision_id | 同一证券、同一期间的具体修订版本 | 当下最新值 |

真实研究应明确 known_at 的含义和证据：交易所披露、行情供应商历史消息或自身可信的采集日志。**没有版本和时间证据，就不能把普通历史数据称为 PIT。**

### 1.1 按时点挑版本的规则

设 i 为证券、f 为指标、t 为信号时刻，c(t) 是已冻结的信息截止。

~~~text
S(i, f, t) = {
    r | r.code = i,
        r.field = f,
        r.period_end <= signal_date(t),
        r.known_at <= c(t),
        r.available_at <= c(t)  # 若独立记录本系统可用时刻
}

chosen(i, f, t) = argmax [period_end, known_at, revision_id] over S
~~~

教学代码先选择**当时已知的最新报告期**，再选该期已知的最新修订；这是一个明确的选择规则，并不是所有财务指标天然共用的标准。TTM、平均权益、会计差错、公告撤回、不同合并口径都需另做规则。

当 S 为空时，记录“当时未知”；不填 0，不从之后披露的版本中回填。

## 2. 五层数据架构：保留事实，不覆盖历史

| 层次 | 核心数据 | 管理原则 |
|---|---|---|
| L0 原始层 | 源文件、下载请求、接收时刻和哈希 | 不覆盖原始快照 |
| L1 版本事件层 | 上市状态、公告、财务修订、行业成员进出 | 以事件追加版本 |
| L2 时点快照层 | 截止某决策时刻的股票池、财务和行业版本 | 可从 L0/L1 重建 |
| L3 研究面板层 | 因子、标签、窗口、缺失原因 | 记录生成规格 |
| L4 交易评价层 | 目标权重、下单、成交、现金及成本 | 保留未成交与拒单 |

证券身份需有稳定键和历史代码映射；不同交易所、股份类别、曾用代码及重新上市情况必须明确区分，不能假定一个简单代码永远唯一。

## 3. 动态股票池需要双条件

对于某个上市状态版本，可定义半开区间：

~~~text
start_on <= signal_date < end_before
known_at <= feature_cutoff
~~~

其中 end_before 是“第一个不再纳入的日期”，为空只表示**这个版本没有记录终点**，不意味着证券未来不会退市。

例：若 B 的退出日期为 2024-03-21，但该条版本直到 2024-03-21 12:00 才可靠可得，那么 3 月 20 日信号不能提前使用该版本。这个数字来自本书的**合成样例**，不是任何真实公司事件。

**最重要的是分离三种资格：**

- **universe_eligible**：按当时已知规则，是否属于研究母体；
- **signal_eligible**：是否允许计算并使用信号；停牌、上市时间过短等需单独定义；
- **can_buy / can_sell**：在特定时刻和具体订单假设下，是否存在执行资格或成交机会。

真实上市但停牌的股票可能仍属于研究母体。即使涨停，也不能把价格观察当作可买到。未来退市的股票，在历史仍符合入池条件时不能事后删掉。

要完整构造母体，至少核查上市、退市、证券身份、交易所日历和资格状态的历史记录；静态存活名单不够。

## 4. 财报：报告期、披露与修订

本章合成财务案例为：

| 证券 | 报告期 | 最早可得 | 教学 ROE |
|---|---|---|---|
| A | 2023-12-31 | 2024-03-15 17:00 | 0.10 |
| A | 2023-12-31 | 2024-04-10 17:00 更正 | 0.15 |
| B | 2023-09-30 | 2023-11-10 17:00 | 0.08 |
| C | 2023-12-31 | 2024-03-25 17:00 | 0.25 |

截止 2024-03-20 15:00，A 应取 0.10，不能使用 4 月的 0.15；B 的最新已知期仍是上一年 9 月末，不能造出一条“年报”。C 还涉及独立的历史股票池成员状态判定，不能因为后来出现财务值，就自动回填到早先研究样本。

注意：教学数据直接存储 ROE 数值，**没有模拟真实财务指标的计算过程**。正式研究需核查归母权益、平均净资产、TTM、合并/母公司口径和历史修订，以及源文件与相关会计规则。

## 5. 行业、指数和题材都是历史版本

如果当前行业分类与历史时期使用的分类体系不同，研究应保存：

1. 分类体系和发布版本；
2. 证券成员的进入/退出生效区间；
3. 该版本的可靠获知时刻；
4. 缺失时的 UNKNOWN 与历史跨版本映射规则。

不能用当前申万一级行业或当前指数成员回填几年前的样本，然后宣称做出了多年历史行业中性化。行业轮动还须保证当周行业收益、预测标签、成员快照和行业版本一致；体系切换时需要有明确的分段规则。

## 6. 缺失不是一个数字

| 状态 | 含义 | 最低处理 |
|---|---|---|
| not_yet_announced | 截止时尚未披露 | 保留未知，不用未来值 |
| not_collected | 数据源可能有但未成功采集 | 标记质量缺口 |
| not_applicable | 指标不适用 | 不做任意数值填充 |
| suspended | 证券行情或交易因停牌受限 | 与一般 NA 分开 |
| source_conflict | 同一版本多个来源互相冲突 | 进入冲突审计 |
| stale | 当前已知版本太旧 | 按预设时效阈值处理 |

“没有 ROE”不代表 ROE=0；“没有成交”不代表收益=0；“没有历史行业”更不能任意代入今天的行业。

为每次历史快照提供：

~~~text
PIT_coverage = 截止时有可信可用值的样本数 / 合格历史样本数
missing_rate = 有缺失原因的样本数 / 应采集样本数
revision_rate = 存在多版记录的实体-字段-报告期数 / 对应总期数
~~~

但覆盖率的分母也需要独立审计。如果动态股票池漏掉退市公司，那么剩下数据“覆盖率 99%”可能毫无意义。

## 7. 动手实验：可复算的 as-of 连接

只使用 Python 标准库，运行：

~~~bash
python examples/advanced_protocol_pit_lab.py
python examples/advanced_protocol_pit_lab.py --json
python -m unittest discover -s tests -p "test_advanced_protocol_pit_lab.py" -v
~~~

阅读 [实验源码](../../examples/advanced_protocol_pit_lab.py)：

- moment()：拒绝无时区输入、统一比较绝对时刻；
- validate_contract()：检查信息、交易与训练/验证时间门禁；
- membership_asof()：按 known_at 取当时最新状态版，再按 [start_on,end_before) 取历史母体；
- facts_asof()：在截止前已知的报告期与修订中取值；
- audit_snapshot()：输出来源、选中版本、覆盖与未满足的证据层级。

**合成预期值**：3 月 20 日截止时仅纳入 A、B；A 的教学值为 0.10，B 为 0.08。C 当时未知的成员记录及 A 后来披露的更正值不得出现。这是对**人工样例**的语义断言，不是市场研究结果。

### 必须验证的边界

| 反例 | 正确行为 |
|---|---|
| 输入时间没有 UTC 偏移 | 直接拒绝 |
| 训练末标签跨过验证首信号 | 要求 Purge |
| 修订晚于特征截止 | 只能使用旧版本 |
| 成员身份直到未来才可得 | 不提前纳入 |
| signal_date 等于 end_before | 排除该成员 |
| 同一事实/时间有重复冲突 | 明确报错 |
| 值为 NaN/Inf | 不进入数值特征 |

上述代码**没有核验源披露真实性、完整退市历史与真实订单回放**。它只验证给定可信事件表后的 as-of 算法边界。

### 7.1 将真实价格的完整性与历史 PIT 分开验证

新增 [真实四股来源与证据审计](REAL_DATA_EVIDENCE_REVIEW.md) 和代码 `python examples/advanced_real_evidence_audit.py --json`。程序校验四份真实 CSV 的 SHA-256、OHLC、采集时刻与 18 期缓存收益，并从原始价格重建特征和标签。

它和本章的合成 `facts_asof()` 实验**验证不同的命题**：固定文件完整不代表 2024 年实际已知。历史价格发生在 2024 年，AKShare 快照采集于 **2026-11-11**。没有供应商当时发布/接收/入库证据，`L3_2024_historical_PIT_availability` 仍为 `NOT_PROVEN`；四股事后固定选择，历史母体门禁为 `FAIL_SELECTED_SURVIVORS`。不要把这些失败状态隐藏在“真实数据已接入”后面。

### 7.2 第二轮进阶实验：带来源版本的真实数据接入合同

上面真实四股案例已经证明：文件完整性不是历史 PIT。下一步必须先定义**可验证的输入门槛**，再考虑扩充实证。本轮新增 [PIT 输入合同实验](../../examples/advanced_pit_intake_lab.py)；它接受本地 JSON，但默认只使用**合成事件版本**。

**最小字段：**

| 事件 | 必填字段 | 作用 |
|---|---|---|
| 研究快照 | `decision_at`、`signal_date`、`validation_first_signal_at`、`universe_scope` | 冻结查询/验证边界及母体声明 |
| 证券成员版本 | `security_id`、`effective_from`、`effective_to`、`revision_id` | 恢复当时成员的半开生效区间 |
| 财务/因子事实版本 | `security_id`、`field`、`period_end`、`revision_id`、`value` | 按可得报告期和修订选值 |
| 每个版本的来源 | `source_ref`、`declared_evidence_sha256`、`source_published_at`、`ingested_at`、`available_at` | 记录原始事件证据和系统可用性，不以今天下载时间倒填 |
| 每个训练标签 | `signal_at`、`feature_available_at`、`decision_at`、`entry_at`、`exit_at`、`label_available_at` | 检查未来信息与逐条标签可得时刻 |

时间戳必须包含 UTC 偏移，并满足：

\[
t_{published}\le t_{ingested}\le t_{available}.
\]

在某个决策截止 `c` 之前，仅允许挑选三个事件时间**都不晚于** `c` 的版本；财务值在已知版本中先按最新报告期，再选该报告期的最新可得修订。若不存在，当时状态是 `UNKNOWN`，**不能自动填 0 或使用未来披露版**。历史证券身份也分 `ELIGIBLE`、`INELIGIBLE`、`UNKNOWN_NO_KNOWN_MEMBERSHIP`。

**重要限制**：提交一个看起来合法的 `declared_evidence_sha256` 或一个带时区的 `source_published_at` 并不证明该事件真实由交易所/供应商在此刻发布。代码只验证**字段与逻辑**，没有检验第三方原始文件内容、供应商当年的发布/接收真实性，也没有自动认定全市场历史母体完整。用户输入的报告始终明确给出 `historical_pit_proven=false`。

### 7.4 第三轮实验：历史母体覆盖率的分母门禁

前两轮解决了“版本时刻怎么筛选”和“现有四股价格是否可复算”，但这还不等于**全市场历史股票池已经建立**。[附录 C：历史证券池与来源覆盖](HISTORICAL_UNIVERSE_SOURCE_AUDIT.md) 给出专门的输入审计程序：

~~~bash
python examples/advanced_universe_coverage_lab.py --real-teaching --json
python examples/advanced_universe_coverage_lab.py --json
python -m unittest discover -s tests -p "test_advanced_universe_coverage_lab.py" -v
~~~

第一种模式对四份真实 CSV 验证哈希、日期并/交集、只在**四只事后固定股票**之间计算重合程度，并且始终返回 `full_market_denominator=null`。第二种模式使用人工 A/B/C 两期版本证明：成员 UNKNOWN 不能等同于已退市；决策时尚未可得的价格也不能当作成交/可用价格。

研究时应明确区分：已知上市范围、已知不合格、未知成员身份、成员已知但行情迟到、行情缺失、供应商来源无法追溯。没有当时真实权威的完整证券母表，不能报告全市场覆盖率。**即使四股样本 117/117 日期完全重合，也绝不意味着 A 股全市场 PIT 覆盖 100%。**

### 7.5 第四轮真实数据：本地 1,453 万条历史证券日，而不是四股样本

此前“只持有四只真实股票”的结论**仅适用于 GitHub 公开仓库**。这一轮通过只读机器学习 MCP 找到本地 `PTradePolicy` 项目早已冻结的 `all_a_membership` Parquet 快照（源为 XC/Tushare）：**2010-01-04—2026-08-03、17 个年度分区、14,536,198 条历史证券日**。2024 年单独包含 **1,296,795** 条；分区 SHA-256 已实测与清单匹配。详见 [附录 C 的实际来源与结果表](HISTORICAL_UNIVERSE_SOURCE_AUDIT.md) 及 [仅含聚合的公开 JSON](local_all_a_2024_aggregate.json)。

### 7.6 继续核验：摘牌日和新旧代码关联，不是“日线随机丢失”

追查 2024 年 60,515 条快照无报价标记后，发现**沪市 16 条、深市 36 条全部恰好位于数据集记录的 `delist_date` 当日**，没有一条 `has_suspend_record=true`。源 SQL 使用 `trade_date <= delist_date`，将摘牌日期也纳入成员，而不保证当日仍有上市交易。这类记录应审计**最后实际交易日与摘牌日的不同语义**，不宜直接判定原始行情缺失。

北交所的 60,463 条则属于**构建快照未成功关联价格**：股票池用当前规范 `920xxx.BJ`，但 2024 年存量股票多以旧 `43/83/87` 代码交易，且部分当年已是 `920` 的新股也未关联。公开的 2024-06-21 成交数据已显示云星宇（当年 `873806`）和万达轴承（`920002`）确实交易，不能说它们在市场上没有报价。2026-11-13 的 AKShare 运行又实证返回云星宇 9.44 元、纬达光电 8.18 元、万达轴承 52.01 元的历史收盘价，均与当日报价记录一致。需要先审 `daily` 原表的交易所覆盖及历史代码映射，再判断能否用于研究。详见 [附录 C 第 2A 节](HISTORICAL_UNIVERSE_SOURCE_AUDIT.md)。

## 8. 研究级数据表最低设计

| 表名 | 最小关键字段 | 用途 |
|---|---|---|
| instrument_events | instrument_id、event_id、known_at | 上市身份、风险状态 |
| membership_versions | instrument_id、taxonomy、valid_from、valid_to、known_at | 历史行业/指数成分 |
| financial_versions | instrument_id、field、period_end、known_at、revision_id | 披露、修订与字段口径 |
| price_events | instrument_id、exchange_time、receive_time、adjustment_version | 价格和公司行为 |
| research_snapshots | study_id、decision_at、input_hash、code_commit | 信号具体使用了哪个版本 |

另须核对交易所日历、费用、复权与实际行情可得时间。这里的 schema 是学习起点，不是生产数据库的完整 DDL。

本仓库的 [数据需求与缺口](../../data/README.md) 记录过一次历史数据快照核查；其覆盖信息有时间边界，不能由旧记录推断现在已经拥有多年 PIT 财务或行业版本。

## 9. 习题与核对答案

**题 1：** 3 月已经披露 ROE 0.10，4 月将同一期修订为 0.15。3 月信号用哪个？

答：用当时确已可得的 0.10；若 3 月原始版也未披露，则缺失。不能使用 4 月修订值。

**题 2：** 一只股票在 5 月退市，3 月研究时是否可以将它从全历史股票池直接删除？

答：不能。若当时仍满足入池条件，应按时点保留，并对之后退市、停牌和无法成交分别处理。

**题 3：** 某股票今天归类为行业 A，五年前分类体系不同，可以回填行业 A 做历史中性化吗？

答：不能。应使用历史体系和当时成员；无证据时标记 UNKNOWN 并限定结论范围。

**题 4：** 最新下载的财务全量表，是否天然等同于 PIT 表？

答：不等同。必须能恢复每个历史决策截止时的可用版本，并对更正、撤回、迟到和缺失留痕。

## 10. 交付边界

**已有**：历史时点定义、版本化设计、财务/成员选择规则、缺失语义、合成 Python 实验与边界测试。

**已新增实证**：找到并核验本地冻结历史成员候选池，2024 年数据源报价缺口已有量化证据。**仍待补**：权威全历史证券分母独立核证、未覆盖上市/退市身份、申万历史成员和财务首次披露时刻、公司行为、执行与压力测试、外部专业审校。不能把候选历史母体升级为全市场严格 PIT。
