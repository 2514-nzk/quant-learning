# 第二卷 · 13｜成交仿真、交易成本与回测状态机

> **状态：教学正文初稿；合成订单和现金账本可复算。** 所有价格、成交量、停牌和限制状态均为人工构造，没有真实盘口、订单队列、交易回报或日期化制度审计，不构成可成交性的真实证据。

## 核心问题：信号以后，真实账户发生了什么？

第 12 章求得的是**目标权重**。目标权重不等于订单，订单不等于成交，成交后的实际仓位又可能与目标不同。本章以最小订单状态机说明从决策到资金账本的不可跳过的环节。

## 1. 严格事件顺序：今天决策，明天才有执行报价

本章的人工价格采用：

~~~text
D日15:05 人工因子可得 → D日18:00 冻结策略目标权重
→ 下一交易日09:30 观察人工开盘报价和限制状态
→ 发出模拟订单/允许部分成交/拒单
→ D+1收盘按人工收盘价估值 → 下一次决策
~~~

上一日选股和风险模型只允许使用上一日收盘之前已知的信息。次日开盘的报价可以用作订单模拟，但**不能反向进入上一日目标权重**。代码检查决策早于下一次开盘。

真实交易所开市日、集合竞价、公司行为、价格限制和结算制度会依证券种类和日期改变，必须取得相应历史规则后才能升级为真实回测。

## 2. 至少要保留六类记录

| 对象 | 核心字段 | 目的 |
|---|---|---|
| 研究决策 | signal、decision、目标权重、数据版本 | 识别前视 |
| 订单请求 | 证券、方向、请求股数、时点 | 保留意图 |
| 成交结果 | 填单股数、模拟价格、费用与拒单理由 | 不把订单当成交 |
| 持仓批次 | 买入日期、剩余股数、可卖数 | 模拟持有期限制 |
| 现金账本 | 买卖后现金、税费、资金可用 | 防止凭空加杠杆 |
| 日终快照 | 持仓、收盘价、现金、NAV | 独立重算收益 |

教材订单事件区分 `FILLED`、`PARTIAL`、`REJECTED`，记录 `requested_qty` 和 `filled_qty`。若卖单被拒，原持仓不应凭空消失；若买单被拒，不能把这部分虚构资产计入净值。

## 3. 现金和净值的两条恒等式

一笔成交数量 q、模拟价格 p、佣金 f、卖出税费 tau：

\[
C^{buy}_{after}=C_{before}-qp-f,\qquad
C^{sell}_{after}=C_{before}+qp-f-\tau.
\]

日终净值：

\[
NAV_t=C_t+\sum_iQ_{i,t}P^{close}_{i,t}.
\]

本书例子采用人工初始资金 100,000 元、买入 100 股整数倍、单侧不利滑点、设定的佣金下限和**仅对卖出的人工税率**。这些都是**合成费用参数**，不代表任何给定日期和交易品种的真实收费标准。真实使用需以历史交易所、券商合同、税率和证券种类为准。

如果订单账本重算的现金和每日净值不一致，应该中止收益解释并修复会计错误，而不是只保留结果曲线。

## 4. 简化 T+1 和交易限制

本轮实验将每次买入保存为带日期的批次；同日刚买入的股数不可卖，之后日期才成为可卖股数。这只是**针对特定 A 股现货场景的概念教学**，没有覆盖 ETF、期货、可转债等不同制度，也未证明某段历史的所有适用规则。

另定义三种**人工**状态：
- `buy_block`：模拟当日买单被阻挡；
- `sell_block`：模拟当日卖单被阻挡，原持仓仍保留；
- `suspended`：两个方向均不能成交。

它们不是交易所盘口撮合真值，也不能仅凭“价格达到涨跌停”简单推断实际成交概率。

订单还受到每证券最多人工日成交量 8% 的上限，模拟价格包含不利滑点和按参与比例增加的冲击。买单遵守整手与现金，卖单不得超过已可卖持仓。程序可能输出部分成交或明确拒单理由。需要特别指出：**通过这些约束后依然假设剩余股数能够成交，没有真实队列、集合竞价或逐笔冲击回放**。

## 5. 为什么目标风险不等于实际风险？

设计划将行业权重从 70% 降至 50%。卖单受限后，实际持仓仍可能接近原先的行业集中程度，而买入另一行业可能失败，现金比例也会偏离目标。

因此运行回测时至少要审计目标与实际权重、交易事件、现金、费用、未成交、持仓可卖、单股和行业实际暴露。**不能只用优化器输出的 target_weights 计算策略 NAV。**

真实研究如果缺少历史未成交或缺少可验证的市场冲击模型，应把结果定位为**理想化成交敏感性分析**，而非实盘可实现的净收益。

## 6. 动手验证：把拒单和部分成交留下来

仓库运行：

~~~bash
python examples/advanced_portfolio_execution_lab.py
python examples/advanced_portfolio_execution_lab.py --json
python -m unittest discover -s tests -p "test_advanced_portfolio_execution_lab.py" -v
~~~

重点阅读：

- `trade_to_target()`：根据目标权重与下一交易日开盘价计算整数股，先卖后买；
- `apply_order()`：执行限制、可卖批次、成交量上限、现金与费用；
- `mark_to_market()`：记录每个合成交易日的现金、股数、收盘标记和 NAV；
- `audit_simulation()`：按事件 notional 和费用独立复算现金；按股票数量和价格复算 NAV；
- `simulate()`：在同一套合成执行规则下对比现金、等权与目标优化。

单元测试主动制造同日买入又卖出、买单限制、卖单限制、停牌、现金不足、成交量上限和账本篡改。测试若发现差异必须拒绝通过，而不是忽略它。

## 7. 习题及答案

**题 A**：原计划买 300 股，模拟只成交 100 股。NAV 按什么计算？

答：以真正模拟成交的 100 股持仓和剩余现金计算；余下 200 股是未成交意图。

**题 B**：同日买入 100 股后要求立刻卖出，若受 T+1 限制，账户现金是否增加？

答：不增加；拒单不产生卖出现金流。

**题 C**：税费极小，但账本 NAV 与持仓/现金核算有 1 元差异，可以跳过吗？

答：不能。应先查明误差来源和金额精度策略，再判断可复算性；不能静默忽略不一致。
