# 工具参考｜量化研究中的 Python 数据处理

这份工具练习适合已经理解基本代码、面板和时间窗口的读者，集中处理 pandas、NumPy 与金融数据的连接。可以在学完数据与算子章节后，按问题选做；语法查阅见[数据分析参考](00a_Python数据分析基础.md)。建议分几次核对，每次先完成一个小例子。

目标是从一张行情表得到：**时点正确的特征、独立保存的未来标签、可追溯的财务版本、明确的评价样本**。这些基础同时服务于传统因子和机器学习。

配套完整脚本：[quant_python_workshop.py](../examples/quant_python_workshop.py)。从项目根目录运行：

```powershell
python examples/quant_python_workshop.py
```

只依赖已有的 NumPy、pandas。脚本内置三只虚构股票、22 个显式教学交易日和两条缺失行情，无需外部数据。它打印计算结果与边界核对，不写文件，不执行交易回测。3 日动量用于看清数值，20 日动量用于理解窗口；样本规模不支持市场有效性结论。

## 1. 用数据库和数组的直觉理解面板

把股票面板看作一张关系表，主键是 `(trade_date, code)`。`code` 用字符串保存，否则 `000001` 可能变成数字 1。价格、收益和金额都要有口径；金融比率存小数，`0.03` 表示 3%，不是 0.03%。

| 任务 | 熟悉的编程概念 | pandas 工具 | 金融数据多出的检查 |
|---|---|---|---|
| 筛选 | WHERE / 布尔条件 | `.loc[mask]` | 条件在决策时是否已知 |
| 按股票算收益 | 分区窗口 | `groupby('code')` | 排序、交易日缺口、复权 |
| 当日选股排名 | 按日期分区排序 | `groupby('trade_date').rank()` | 股票池与并列规则 |
| 连接日指标 | JOIN | `merge` | 是否重复键、是否一对多膨胀 |
| 连接已公告财务 | 时点状态查询 | `merge_asof` | 可用时刻、修订、有效期限 |
| 批量数值运算 | 数组广播 | NumPy | 轴、单位、标签是否已对齐 |

三个经常混淆的输出形状：

- `agg`：一组变一行，例如每天平均收益。
- `transform`：一组算完后回到原行数，例如给每只股票附上当日均值。
- `apply`：自定义形状，索引行为更复杂；有前两种方法时优先用它们。

不要用 `.reset_index(drop=True)` 猜测性地修复错位。先检查结果索引到底代表日期、股票还是原始行号。

## 2. pandas 按标签对齐，NumPy 按位置计算

这是程序员转做量化时容易写出“能运行但结果错”的地方。以下是独立可运行的例子：

```python
import numpy as np
import pandas as pd

returns = pd.Series([0.10, -0.02], index=['A', 'B'])
weights = pd.Series([0.80, 0.20], index=['B', 'A'])

# 明确以 returns 的证券顺序对齐，且缺权重时先报错。
aligned = weights.reindex(returns.index)
assert aligned.notna().all()
right = aligned.to_numpy() @ returns.to_numpy()
wrong = weights.to_numpy() @ returns.to_numpy()
print(f'对齐后：{right:.2%}；直接按位置：{wrong:.2%}')
assert np.isclose(right, 0.004)
assert np.isclose(wrong, 0.076)
```

正确组合是 A 权重 20%、B 权重 80%，收益 `0.2×10%+0.8×(-2%)=0.4%`。直接丢掉索引后计算得到 7.6%。两段程序都不报错，只有一个符合持仓含义。

pandas 乘法本身会对齐标签，但默认求和可能跳过缺失。不能让没有收益数据的持仓悄悄消失；先核查完整性，再决定估值规则。

## 3. 从原始行情到完整交易日网格

配套脚本的 `make_market_data()` 创建 64 行行情：3 只股票 × 22 个日期，本应 66 行，B 缺了两天。缺行只是事实，真实原因需要查数据源或交易状态。

下列代码可以作为一个整体，从项目根目录的 Python 会话执行。后续“续接代码”沿用这里的变量：

```python
from examples.quant_python_workshop import (
    make_market_data, build_panel, attach_labels,
    point_in_time_example, evaluate_daily, verify_workshop,
)

calendar, raw = make_market_data()
panel = build_panel(raw, calendar)
sample = attach_labels(panel, raw, calendar, horizon=5)
pit = point_in_time_example()
verify_workshop(raw, calendar, sample, pit)
print(len(raw), len(panel))  # 64 66
```

`build_panel()` 先检查重复键、非法价格和日历，再生成证券 × 市场日历的网格。B 缺失日期的价格是 `NaN`，不会自动填成前收盘价或零。

真实全市场数据不一定要生成巨大的笛卡尔积，可以按历史上市区间、日期分区或显式日期连接处理。小样本先使用完整网格，是为了让每一行的市场日期含义清楚。

`pd.bdate_range()` 只生成一般工作日，无法表示中国交易所的节假日与特殊安排。真实标签和调仓日必须由适用交易所日历提供。

## 4. 时间序列特征：窗口、缺失与可用日

同一股票内、日期升序后计算：

```text
ret_1d(T) = close(T) / close(T-1) - 1
mom_3(T) = close(T) / close(T-3) - 1
mom_20(T) = close(T) / close(T-20) - 1
vol_5(T) = std(ret_1d(T-4), ..., ret_1d(T), ddof=1)
```

核心实现可在脚本中逐行阅读：

```python
# 续接第 3 节变量，只演示单独计算。
check_mom = panel.groupby('code')['close'].pct_change(3, fill_method=None)
check_vol = panel.groupby('code')['ret_1d'].transform(
    lambda s: s.rolling(5, min_periods=5).std(ddof=1)
)
```

`fill_method=None` 明确关闭收益率计算前的隐式填充。若昨天缺价，今日单日收益也应缺失；若一个 5 日波动窗口没有 5 个有效单日收益，就保留缺失。改变 `min_periods` 是研究规格变化，需要记录。

动量只依赖两个端点；即使中间缺一天，两个端点齐全时，端点比率仍可能可计算。波动率依赖窗口内的单期收益，不能用同一缺失规则解释两者。

脚本中 A 每期上涨 1%，所以：

| 核对项 | 预期 |
|---|---|
| A 最早三行 `mom_3` | 缺失，因为没有 T-3 端点 |
| A 第四行 `mom_3` | `1.01³-1=3.0301%` |
| A 第 21 行 `mom_20` | `1.01²⁰-1≈22.0190%` |
| B 缺行后第一个有价日的 `ret_1d` | 缺失，不能跳过中间日期当单日收益 |

`rolling(20)` 通常含当前值，覆盖 T-19 到 T；`pct_change(20)` 比较 T 与 T-20，需要端点跨越 20 期。完整连续价格表通常需 21 行才能计算后者。

## 5. 横截面：同一天比较股票

脚本先确定 T 时点的 `signal_eligible`，再计算因子排名。教学资格仅要求当前存在观测和动量可计算；真实资格还要增加历史状态正确的上市时长、ST、流动性等条件。

默认 `rank(method='average', pct=True)`：有效股票中的平均名次 / 有效数量。`[10,20,20,缺失]` 的结果是 `[1/3,5/6,5/6,缺失]`，不是每只股票都有不同名次。

选 Top-N 时，可以按“分数降序、代码升序”固定并列顺序。这是组合选择规则，不应倒过来改变统计相关中的并列语义。

```python
# 续接第 3 节变量。仅使用信号日已知字段生成候选。
date = calendar[6]  # 2024-01-10
candidates = panel[panel['trade_date'].eq(date) & panel['signal_eligible']]
target = candidates.sort_values(['mom_3', 'code'], ascending=[False, True]).head(2)
print(target[['code', 'mom_3', 'rank_pct']])
assert target['code'].tolist() == ['A', 'C']
```

这一步产生目标候选，还没有模拟成交。不能先用 `fwd_return.notna()` 或未来能否卖出筛选，再声称这是 T 日的真实选股结果。

## 6. 未来标签：按日历连接，不按稀疏行数移动

本教材的计划收益定义为：

```text
T 日收盘后形成信号
entry_date = 全市场日历中的 T+1
scheduled_exit_date = 全市场日历中的 T+5
fwd_return = 该退出日复权收盘价 / 该入场日复权开盘价 - 1
```

脚本先在完整日历上生成日期映射，再把入场价和退出价连接到信号行。`merge(..., validate='many_to_one')` 检查价格表同一证券和日期只能有一个值；上游重复键应先解释，不能靠 `drop_duplicates(keep='last')` 隐藏问题。

脚本的 2024-01-10 核对表：

| 股票 | mom_3 | rank_pct | T+1 | T+5 | fwd_return |
|---|---:|---:|---|---|---:|
| A | 3.0301% | 1 | 01-11 | 01-17 | 约 4.2685% |
| B | -1.4925% | 1/3 | 01-11 | 01-17 | 缺失：入场日缺价 |
| C | 0.5613% | 2/3 | 01-11 | 01-17 | 约 -0.6549% |

若在 B 的原始稀疏表上做 `shift(-5)`，会错落到 01-18。`shift` 不认识交易所日历，它只认识行的位置。

缺失标签不等于收益为零。研究末尾的标签尚未实现、入场价缺失、退出价缺失，都要分别核查。评价时可以只使用有效配对，但应报告覆盖和原因，不能将删除后的结果直接当作可实现账户收益。

## 7. PIT 财务连接：选择当时看得见的状态

`point_in_time_example()` 给出两个股票的公告状态。A 在 01-04 20:00 公布 EP=0.04，在 01-10 20:00 修订为 0.08；信号截止统一为 16:00。

| A 的决策时间 | 应得到 EP | 原因 |
|---|---:|---|
| 01-04 16:00 | 缺失 | 首次公告尚未可用 |
| 01-05 16:00 | 0.04 | 初始版本已可用 |
| 01-10 16:00 | 0.04 | 当天晚间修订仍不可见 |
| 01-11 16:00 | 0.08 | 修订版本已可用 |

核心参数：

| 参数 | 含义 | 易错点 |
|---|---|---|
| `left_on/right_on` | 决策时间与可用时间 | 报告期不是可用时间 |
| `by='code'` | 同一股票内匹配 | 不能让另一股票的公告流入 |
| `direction='backward'` | 只找不晚于决策时点的状态 | `nearest` 可能选到未来 |
| `allow_exact_matches=True` | 截止时刻相同且确认已可用时允许匹配 | 无法确定接收先后时应更保守 |
| `tolerance=30 days` | 本小例子的教学过期规则 | 不是通用财务有效期限 |

两表的**连接时间键必须整体升序**。只按 `code, time` 排序，可能在从 A 切换到 B 时导致时间倒退。

本例事件表已整理为“该时点最新适用指标状态”。真实财务库还包含报告期、报表类型、修订及累计/单季等维度：必须先按报告版本规则构造状态，不能把所有公告直接喂给 `merge_asof`，否则迟到的旧报告可能覆盖新报告。详见 [传统因子与预处理](03b_传统因子与预处理.md)。

## 8. 评价必须同时报告样本数量

脚本按日期分别计算 RankIC，同时保存：

```text
n_signal：在 T 日有可用信号的股票数量
n_evaluable：信号和未来收益都有效的配对数量
label_coverage = n_evaluable / n_signal
rank_ic：这些有效配对之间的排名相关
```

```python
# 续接第 3 节变量。
report = evaluate_daily(sample)
print(report.iloc[5:10])
```

在 01-10，信号有 3 只，评价配对只有 2 只。本练习要求至少 3 对才输出 RankIC，所以该日为缺失。3 只是演示阈值；真正的研究需要预先设定适合股票池的样本门槛，并检查行业和规模覆盖。

不要因为 `groupby().apply()` 最后只保留有效日期，就遗漏被跳过的样本。完整评价表应保留无定义日期及其原因。

## 9. 安全计算与向量化边界

对分母接近零的比率，应先定义无效条件，再计算。以下是独立例子：

```python
import numpy as np

profit = np.array([8., 2., -2.])
equity = np.array([40., 0., -20.])
valid = np.isfinite(profit) & np.isfinite(equity) & (equity > 1e-8)
roe = np.full(profit.shape, np.nan)
np.divide(profit, equity, out=roe, where=valid)
assert np.isclose(roe[0], 0.2)
assert np.isnan(roe[1:]).all()
```

`np.where(valid, profit/equity, np.nan)` 仍可能先计算两支表达式，产生除零警告；`np.divide(..., where=...)` 可以明确控制计算。阈值必须对应字段单位，`1e-8` 只是此数组例子的约定。

适合向量化的任务包括算子、排名、窗口和同口径数值计算。现金、未成交、可卖数量等跨日状态可以用清楚的逐期循环维护；不要为消灭循环而把未来状态提前写进数组。

性能优化顺序是：核对公式与时点 → 剪裁需要的日期和列 → 优先 `agg/transform` → 减少复制与全表 `apply` → 测量热点。数据库读取可把筛选和聚合下推到 SQL，再取小结果；不要为了一个教学实验反复把全库装进内存。

## 10. 进阶阅读：数据接口与可复现性

输入约定应包含主键、字段类型、日期/时区、单位、价格口径、缺失规则和数据版本。CSV 读取时显式保留证券代码字符串并解析日期；中间文件可以使用保留类型的列式格式，但要确认所需引擎已经存在。当前脚本全部用内置数据，便于核对计算本身。

显式区分三个集合：

- **特征白名单**：T 时点已知的动量、波动、财务状态等。
- **结果字段**：未来价格、收益、实际退出时间等。
- **审计字段**：信号资格、缺失原因、可用时间、数据版本等。

字段在同一张 DataFrame 不代表它们都能传入模型。把字段白名单写出来，比根据“数值列”自动取特征更容易审计。

## 11. 练习与答案

| 练习 | 预期结果或答案要点 |
|---|---|
| 在原始行情重复插入一行再构造面板 | 拒绝重复键；不能静默选择最后一行 |
| 解释原始 64 行为何变成 66 行 | 补齐共同市场日历的位置，两处行情仍为缺失 |
| 核对 A 的 3 日和 20 日动量 | 约 3.0301%、22.0190%；后者第一次需要第 21 行价格 |
| 对比 B 的行位移与市场 T+5 | 01-10 信号的真实 T+5 是 01-17，稀疏行位移落在 01-18 |
| 把所有缺失价格前向填充后再算单日收益 | 缺行后收益和覆盖改变；填充价不自动成为可成交价，需另立规则 |
| 将 01-10 晚间修订回填当天 16:00 | 应判前视错误；正确 EP 仍为 0.04 |
| 把最后一天的价格乘 100，再看过去特征 | 过去特征不变；包含该未来日的历史标签可以改变 |
| 将评价阈值从 3 对改为 2 对 | 日期覆盖扩大，两对非并列样本的相关只能是 ±1，不能据此夸大有效性 |

脚本中的 `verify_workshop()` 已自动核对重复键、窗口首值、缺行、并列、修订、未成熟标签和未来不变性。完成后应能不用脚本解释每个断言的研究含义。

这份工具材料用于核对正文中的数据计算。需要解释均值、排名相关和误差时，再查[数学与统计工具](00e_量化数学与统计.md)的对应小节，完成后接着原来的章节向前读。
