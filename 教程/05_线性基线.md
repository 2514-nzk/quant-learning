# 第 5 章：先让简单模型成为标尺

## 1. 为什么基线优先

如果 LightGBM 不能稳定超过等权因子或 Ridge，那么额外复杂度没有被证明有价值。复杂模型还会增加调参自由度、训练成本和解释难度。

## 2. 三类基线

等权因子的具体计算已在 [第 9a 章](09a_多因子合成与综合实训.md) 给出。用于模型比较时，必须重新对齐到本章相同股票池、5 日标签、样本外日期和交易成本；不能直接拿月度 Top-50 与 5 日 Ridge 的净值比较。当前自动运行入口比较三类模型，传统 EP/ROE 合成需先完成数据接入，不会因新增讲义自动出现在结果文件中。

- 常数/均值预测：检查评价代码是否正常。
- 等权因子：把方向一致的 Rank 特征平均。
- Ridge：线性回归加 L2 正则，适合相关特征较多的情况。

Ridge 的目标可以理解为：一边减少预测误差，一边惩罚过大的系数：

```text
min_beta sum_i (y_i - x_i * beta)^2 + alpha * sum_j beta_j^2
```

`alpha` 越大，系数越保守；但 `alpha` 必须由验证集选择。Lasso 把平方惩罚换成绝对值惩罚，可能把部分系数压到零，适合做稀疏基线，但在强相关特征间的选择可能不稳定。

如果把问题改成“未来收益是否进入当日前 20%”，可使用 Logistic Regression，并用 AUC、PR-AUC 和概率校准评价。分类标签会丢失排序细节，因此本项目主线仍使用回归预测 Rank。

## 3. 评价方式

不要把 `R²` 当作选股唯一指标。金融横截面模型常见的微弱预测力未必产生高 R²。至少同时看：每日 RankIC 的均值和分布、ICIR、分组收益是否单调、Top 组收益、跨年度稳定性。

模型系数是条件相关，不是因果结论。系数方向频繁反转通常提示共线性、分布漂移或经济逻辑不稳。

## 4. 代码入口

`src/research.py` 中的 Ridge 先只在 Train 拟合 `StandardScaler`，用 Validation 从 `ridge_alphas` 选择 alpha；规格冻结后在 Train+Validation 重新拟合 scaler 和模型，再预测 Test。样本外预测被保存到 `predictions.csv`，而不只是保存最终净值。

## 练习

固定其他条件，把 `ridge_alphas` 设为 `[0.1, 1, 10, 100]`。只用验证期选择候选值，记录系数稳定性、RankIC 和 Top 组收益，不要根据最终测试总收益挑选。

## 5. 标准化为什么重要

Ridge 的惩罚项直接作用在系数上。如果一个特征以元计价、另一个特征以百分比计价，量纲差异会让惩罚不公平。标准化后，系数更容易比较：

```text
z_j = (x_j - mean_train_j) / std_train_j
```

这里的均值和标准差只能由 Train 估计。当前 `src.research._fit_predict` 在候选 Ridge 阶段使用 Train 的 `StandardScaler`，选定 alpha 后再用 Train+Validation 重新拟合 scaler 和模型，Test 只做变换和预测。

树模型对标准化不敏感，但为了让不同模型的输入契约清楚，研究报告仍应记录是否做了标准化、缺失值如何处理、是否做了截尾。

## 6. 训练、验证和测试的职责

一次滚动折中的正确顺序是：

1. 用 Train 拟合候选 alpha；
2. 在 Validation 计算每日 RankIC 的平均值；
3. 选择验证分数最高的 alpha；
4. 把 Train 和 Validation 合并重新训练；
5. 对 Test 生成一次预测并保存。

不能先看 Test 再决定 alpha，也不能用 Test 的均值和标准差标准化。若多个 alpha 的验证差异极小，应优先选择更简单、更稳定的规格，并在报告中说明选择规则。

## 7. 四特征手算直觉

假设两只股票只有一个标准化特征：A 的 `z=1`、B 的 `z=-1`，Ridge 系数为 `0.02`，截距为 `0.5`，则预测分别为 `0.52` 和 `0.48`。模型只需要把 A 排在 B 前面，并不需要准确预测未来收益的绝对百分比。

加入第二个特征后，预测是各项贡献之和：

```text
prediction = intercept + beta_mom * z_mom + beta_vol * z_vol
```

若 `beta_vol` 为负，表示在控制其他特征后，高波动样本的预测排名更低；它是模型的条件相关，不等于“低波动因子一定有因果收益”。

## 8. Ridge、Lasso 和 Logistic 的选择

- Ridge：保留所有特征，遇到高度相关特征时通常更稳定；
- Lasso：可能把系数压到零，适合做稀疏性探索，但相关特征之间可能随机择一；
- Logistic Regression：输出分类概率，适合上涨/进入前 20% 等分类标签，不应直接套用回归标签和 RankIC 解释。

模型名称改变时，标签、损失函数、评价指标和组合使用方式都要一起记录。不要为了使用一个熟悉的分类器，把连续收益排名粗暴地切成 0/1 后仍沿用同一套结论。

## 9. 基线结果如何验收

运行后至少检查：

- Ridge 的每折选中 alpha 是否只来自验证集；
- `predictions.csv` 是否包含所有样本外日期和模型名；
- RankIC 是否按交易日计算，而不是把所有股票行直接算一个相关系数；
- Top-N 组合是否与预测排序方向一致；
- Ridge 与更复杂模型比较时，样本、切分、成本和持有期是否相同。

如果常数基线表现异常，先检查指标代码；如果 Ridge 训练指标很高、测试 RankIC 迅速变差，先检查泄漏、特征漂移和正则化，而不是马上增加树模型复杂度。

练习答案框架：先画出 Train→Validation→Test 的数据流，再说明 scaler 在哪一步拟合；最后比较 alpha 的验证分数和测试分数。若挑选规则使用了测试分数，答案应判定这次测试已经被污染。
