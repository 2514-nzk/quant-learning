# 第三卷 · 12｜研究到实盘：数据、订单与治理

**先看一个实际问题：程序发出买单后网络超时，重启时能再发一次吗？**

不能直接重发。你不知道第一笔是否已经被券商接受，甚至可能已经部分成交。若程序将超时理解成失败，第二笔订单就可能重复买入。真正的交易系统首先要能处理“不知道”。

本章只用本地人工纸面账本做故障演练，不连接真实账户，不提供实盘下单接口。

## 1. 每天的研究与交易怎样接起来？

| 阶段 | 必须检查 | 失败怎么办 |
|---|---|---|
| 盘前 | 交易日历、行情与公告可用时刻、账户快照 | 数据过期则禁止生成新订单 |
| 决策 | 策略版本、信号时间、风险预算、目标权重 | 记录拒绝原因 |
| 委托前 | 实际持仓、可卖数量、未成交单、现金预留 | 按净差额重新计算 |
| 委托后 | 客户端订单号、券商订单号、成交事件号 | 超时转 UNKNOWN |
| 收盘后 | 现金、证券、委托和成交逐项核对 | 不一致则冻结、调查 |

例如前日收盘信号不能使用次日集合竞价结果回写；盘前任务的具体启动时刻要配合数据到达及历史交易制度，而不是固定认为某个时钟一定可交易。遇到次日大幅高开，应按事先约定的限价、取消或重新审批规则执行，不得事后挑有利价格。

## 2. 订单不只是成功或失败

本章状态机：

~~~formula
OPEN → PARTIAL → FILLED
OPEN / PARTIAL → UNKNOWN（超时、结果不确定）
OPEN / PARTIAL / UNKNOWN → CANCELLED（确认撤单后）
~~~

UNKNOWN 不是拒单。只要可能仍有未成交量，现金或可卖数量就不能释放。成交事件即使在冻结期间到达也要按规则入账；冻结只拦截新意图，不应丢弃真实回报。

限价买单的剩余资金预留：

\[
C_{\mathrm{reserved}}=\sum_j(q_j-q_j^{filled})p_j^{limit}.
\]

本章为了容易手算使用整数分，不计交易费；完整费用逻辑请见第二卷。真实交易还要预留费用、考虑部分成交计费和结算规则。

## 3. 幂等：同一份意图只能创建一次

给每个交易意图设置稳定键，例如 D1:S01:BUY:1，重启后仍用同一个键。若键和内容完全相同，返回原有意图；若键相同但数量、价格、证券或日期不同，标记冲突并冻结。不能通过生成新随机 ID 来掩盖重试。

成交回报也要用独立事件号去重。一笔真实成交只记一次，重复收到不应重复扣钱。事件号相同但内容不同必须停下来对账。

本章 snapshot 可序列化为 JSON，再重新构造账本，检验重启后同一个订单和成交事件仍被识别。它模拟持久化语义，而不是真正的事务数据库：生产需要原子事务、幂等键唯一约束、持久 outbox、认证与券商回报契约。

## 4. 动手：先成交一半，再断线

初始纸面现金 10,000 元，买 200 股，限价 10 元。先成交 100 股，每股 9.90 元。

| 项目 | 预期手算 |
|---|---:|
| 初始现金 | 10,000 元 |
| 已扣现金 | 990 元 |
| 剩余现金余额 | 9,010 元 |
| 剩余订单预留 | 1,000 元 |
| 可用于新订单的现金 | 8,010 元 |
| 当前持股 | 100 股 |
| 当日可卖 | 0 股 |

接下来人工注入超时、重复提交、重复回报、重启及错误对账。只有确认剩余订单取消，现金与持仓及订单和事件一致、数据仍属于正确会话且获得人工审批，才能恢复新订单。下一模拟时段才释放当日买入的可卖数量。

运行 [纸面故障实验](../../examples/volume3_capstone_lab.py)：

~~~bash
python examples/volume3_capstone_lab.py --chapter 12
python examples/volume3_capstone_lab.py --json
~~~

查看 paper.outcomes、snapshot.orders、events、cash、holdings、available、audit。示例的模拟券商快照是人为构造的对照，不是真实独立券商数据。重复成交不会改变现金和数量；对账差一分钱也禁止恢复。

**动手注入故障：** 选择是否先部分成交、重启后重复提交次数、是否收到确认撤单、对账是否一致和是否获得人工批准。观察订单状态、持仓、现金及预留资金如何改变。同一订单和事件编号不得重复记账。假定数据会话有效，实际系统仍需要完整故障状态机与独立券商对账。

## 5. 停机与恢复不是同一件事

| 故障 | 行为 |
|---|---|
| 过期数据 | 冻结新委托，保留持仓和订单 |
| 超时 | 保留预留资金，进入 UNKNOWN |
| 重复订单或回报 | 原意图/事件不重复记账 |
| 同键不同内容 | 冻结，审计冲突 |
| 对账不一致 | 冻结，调查缺失成交或状态 |
| 人工恢复 | 已确认状态、对账通过、数据有效、批准后才恢复 |

实际生产还需要断网、重连、回报乱序、跨日未完成委托、重放日志、进程并发、交易所撤单限制、券商限流、数据许可和账户权限等单独验证。不能以本地故障演练代替券商沙箱验证。

## 6. 习题与答案

**题 1：** 买入 200 股已成交 100 股，超时后还能用剩余订单预留的资金吗？

答：不能。只有终态确认或成交明确更新后才能释放相应预留。

**题 2：** 本地和券商现金差 0.01 元，但净值曲线差不多，可以继续吗？

答：不能以曲线相近代替对账。先冻结，定位费用舍入或遗漏回报。

**题 3：** 数据正常了就能自动恢复吗？

答：本实验不允许。还要对账、解决未知订单、核对会话并人工批准。
