# 第二卷 · 01｜研究问题与可证伪实验合同

> **状态：教学版 v1 方法与例题内部校审完成；合成时间门禁实验可复算。** 未进行真实 A 股统计检验、交易回放或策略验证。实验数据及公司均为人工构造。

## 学习目标

第一卷教我们计算选股收益。第二卷先回答更根本的问题：**结果能算出来，不代表研究能被信任。**

学完本章，你应能把市场直觉改写成可否定的研究假设，在结果产生前冻结信息时点、基准、标签与失败标准；还能识别模型排序、组合收益、真实成交三种不同证据。

## 1. 从市场直觉到可以被否定的命题

“跌得多的股票容易反弹”不是完整假设，因为没有定义跌幅窗口、交易品种、持有期、基准和失效条件。观察多个窗口后只公布表现最好的一个，也不能算独立验证。

可将它转换为示例研究问题：“在某一事先冻结的 A 股历史股票池中，以当时可知的 20 日反转评分预测下一周相对收益，预先检验逐期 RankIC 是否存在持续正向排序信息，并检查成本后组合是否提供独立超额。”这里的窗口、方向和评估对象只是**教学规格**，不是已被证实的结论。

单因子零假设可以写成：

~~~text
H0：E[IC_t] = 0
H1：E[IC_t] > 0（仅适用于预先约定的单侧检验）
IC_t = Spearman({factor_i,t}, {future_return_i,t})
~~~

注意：每个 t 的 IC 是某一时刻的横截面排名相关，不是把所有股票和所有日期的观测简单堆成一个巨大样本。周度 IC 可能有自相关或结构变化，推断需要相应的方差估计与稳健性检验。

即使 H0 在某种检验下被拒绝，也不等于策略能赚钱：行业/规模暴露、调仓、成本、流动性、资金容量和实际成交都尚未解决。

## 2. 一份研究合同至少包含九组信息

| 组别 | 事前必须定义 | 禁止的捷径 |
|---|---|---|
| 01 研究问题 | 研究 ID、机制、方向、零假设和失败条件 | 看完回测再编机制 |
| 02 研究对象 | 市场、证券类型、历史股票池、版本切换 | 用今天的成分股代表过去 |
| 03 数据与特征 | 因子表达式、窗口、可用时点、缺失语义 | 把财报报告期当披露日 |
| 04 决策时点 | signal、decision、feature cutoff、时区 | 使用决策后信息 |
| 05 交易和标签 | entry、exit、label_end、收益与公司行为 | 用理想报价当真实成交 |
| 06 比较基准 | 朴素信号、市场/行业对照、费用与容量 | 只选容易战胜的基准 |
| 07 训练验证 | 切分、Purge、参数搜索、冻结 OOS | 用测试集调模型 |
| 08 组合约束 | Top-N、换手、持仓、拒单、现金、止损 | 无条件假设全部成交 |
| 09 判定与归档 | 统计区间、停止条件、代码与数据指纹 | 只保留成功实验 |

这九组是**项目管理字段**，不是行业通用“九条定律”。可以按策略新增字段，不应省略对结果有实质影响的约束。

### 三种证据等级

1. **排序信息**：逐期 RankIC、分层单调、衰减和置信区间，回答排名是否有信息。
2. **组合证据**：成本后净值、风险、基准超额与参数敏感性，回答信号是否能转化为投资组合表现。
3. **执行证据**：真实可得订单、成交率、排队、滑点和容量，回答观察到的理论交易是否能够实施。

可能出现“IC 正且稳定，但多头成本后不赚钱”，也可能出现“条件交互显著，却无法复制到后续时期”。这些都应该是允许写进研究结论的结果。

## 3. 时间合同：交易日不等于事件时刻

本仓库的合成实验采用下面的北京时间时间线（**仅用于代码验证，不是历史实盘记录**）：

| 事件 | 合成时刻 | 含义 |
|---|---|---|
| feature_available_at | 2024-03-20 15:00 | 当前特征所需信息最晚可得时点 |
| signal_at | 2024-03-20 15:00 | 信号横截面锚点 |
| decision_at | 2024-03-20 18:00 | 模型和组合决定被冻结 |
| entry_at | 2024-03-21 09:30 | 计划入场观测时刻 |
| exit_at | 2024-03-28 09:30 | 计划退出观测时刻 |
| label_end_at | 2024-03-28 09:30 | 标签最后一条价格或事件时刻 |
| train_last_label_end_at | 2024-03-19 09:30 | 训练区最后一个标签结束时刻 |
| valid_first_signal_at | 2024-03-20 15:00 | 验证区第一个信号 |

至少需满足：

~~~text
feature_available_at <= decision_at < entry_at < exit_at <= label_end_at
signal_at <= decision_at
max(train.label_end_at) < min(valid.signal_at)
~~~

最后一项是此教材采用的严格切分边界。若标签结束后仍需等待行情入库、清算或数据校验，那么**可用于训练的时刻**还应后移，而不能仅把最后报价形成时刻当作已知结果。

每条时间戳都需要时区。跨境资产尤其不能使用“日期相同”判断信息已知：美股在美国当地周五收盘，并不意味着中国市场周五作出决策时已经知道该收盘价。应统一比较带时区的绝对时刻。

### 生效、公开、入库是三件不同的事

- **effective_at**：事实对应的时期，例如行业归属生效日或财报报告期；
- **known_at**：有可靠来源证据的最早公开可得时刻；
- **ingested_at**：研究系统实际接收并通过校验的时刻。

2023 年 12 月末的财务报告，如果到 2024 年 4 月才披露，就不能进入 2024 年 3 月的信号。真实系统还需考虑延迟接入与版本修订：保留最初披露版本，不能使用后来更正的报表回填历史。

**无法证明 known_at，就不能仅凭表格中的数值声称 PIT 合规。** 第 05 章会把这个条件转换为可执行连接。

## 4. 从探索到确认：测试集不是无限使用的资源

建议明确区分：

- **探索集**：提出假设、认识失败、缩小候选空间；
- **验证集**：在既定范围选择因子、超参数和交易约束；
- **最终确认 OOS**：设计冻结后只作确认，不允许反复查看并继续称为未触碰的测试。

如果周频训练标签跨越验证信号，即便训练信号本身早于验证时段，也可能有标签泄漏。Purge 应根据每条样本的实际 label_end 计算，不能机械删除固定五行。Embargo 是另一类依赖缓冲约束，两者应分别说明。

滚动 OOS / Prequential 研究也应保存每次当时可用的训练快照、模型版本与配置。今天重新跑一段旧数据，并不自动获得“历史前瞻”的证据身份。

### 事前失败规则怎样写？

研究合同应至少允许四类决议：

1. **数据门禁未通过**：历史时间证据或动态股票池不完整，暂时停止收益研究。
2. **统计证据不足**：均值效应不稳定、区间跨零、对照组无差异。
3. **有排序但不可交易**：正的排序信息在交易成本、换手与容量约束后消失。
4. **继续研究但不得宣称通过**：样本少、测试集已被多次使用、执行证据不足。

具体的显著性、覆盖率、收益和风险阈值取决于研究问题，必须在观察验证结果前给出；本书不会把某个 IC 阈值写成普遍真理。

## 5. 最低可复现研究包

~~~text
research_contract (研究合同和版本)
  -> raw_snapshot + provenance (原始记录、来源、发布时间)
  -> asof_panel + audit (PIT 特征和质量检查)
  -> folds + label_end + purge_log (标签与时间切分)
  -> baseline_and_candidates (统一基线和候选)
  -> frozen_OOS_report (确认结果与不确定性)
  -> portfolio/order_ledger (交易层，适用时)
  -> conclusion/failures (结论和失败日志)
~~~

保存研究 ID、代码 commit、数据版本/哈希、配置、时区、参数搜索次数、是否看过测试集、执行限制与未成交记录。报告中不要用“最终最终版.csv”覆盖历史失败证据。

## 6. 动手实验：让错误的时间配置无法运行

实验文件：[advanced_protocol_pit_lab.py](../../examples/advanced_protocol_pit_lab.py)，使用 Python 标准库和**合成** A/B/C 股票。项目根目录运行：

~~~bash
python examples/advanced_protocol_pit_lab.py
python examples/advanced_protocol_pit_lab.py --json
python -m unittest discover -s tests -p "test_advanced_protocol_pit_lab.py" -v
~~~

validate_contract() 检查九组合同中的关键标识、研究描述及时间边界；moment() 解析 ISO 时间并换算 UTC；单元测试拒绝无时区、晚于决策的特征和与验证信号重叠的训练标签。

试把 sample_contract() 中的 feature_available_at 改为 2024-03-20T19:00:00+08:00，或将 train_last_label_end_at 改成与 valid_first_signal_at 相同。代码应该**拒绝**，而不是自动修改输入。

**这只证明编写的几条时间规则能被检查，不证明完整数据集无泄漏。** 真实研究还要逐行导出 label_end、known_at 与切分日志，并验证来源是否可信。

## 7. 练习与答案

**题 1：** 2023 年报在 2024 年 4 月披露，2024 年 3 月信号能否使用其中数值？

答：不能；只能使用 3 月时已公开版本，没有则记缺失。

**题 2：** 一个因子的逐期 RankIC 是正的，可否直接写“已形成可交易 Alpha”？

答：不能；需要独立比较、组合和成本后收益、成交及容量证据。

**题 3：** 训练标签结束于验证信号当日 15:30，而验证信号是 15:00，是否可以保留？

答：不可以；按本书严格切分要求，应清除跨越边界的训练标签。

**题 4：** 根据最终 OOS 表现反复调整窗口，还能说测试集未触碰吗？

答：不能。该时段已经进入模型选择过程，应降级其证据身份或使用新的独立验证。

### 质量核对｜标签结束与真正可训练时间

设一条历史训练样本的最后报价在 2024-03-19 09:30 已形成，但直到 2024-03-20 **15:10** 才能被模型读取；验证首个信号为 2024-03-20 **15:00**。**问：可保留吗？**

**答：不可保留。** 标签结束早于验证还不充分；因为 \(a_j=15{:}10>v_k=15{:}00\)，不满足第 06 章统一的**标签实际可用时刻严格早于验证首信号**约定。研究合同必须分别冻结标签形成和可训练时刻。
