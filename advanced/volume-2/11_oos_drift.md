# 第二卷 · 11｜严格 OOS、漂移与模型增量检验

> **状态：教学版 v1 方法与例题内部校审完成；合成时间前推/漂移实验可复算。** 本章中的后段数据是我们合成的开发演示，并非独立真实市场 OOS。反复查看这些结果后，不能把它重新包装成“未触碰测试”。

## 本章最关键的问题：我们到底还有多少独立证据？

第 09 章告诉我们要与简单因子做配对增量，第 10 章介绍如何训练预测与排序模型。到了第 11 章，最危险的错误通常不是代码明显读取了未来收益，而是**研究者本人**看过测试结果后不断改变特征、调参和停止规则。

真实证据强度取决于：可用数据、时间切分、研究自由度、是否冻结开发过程、模型与执行约束是否经过完整审计。

## 1. 时间分割只是开始，不是全部

在单纯的历史日期划分上写出 “train 2020–2022 / valid 2023 / test 2024” 不代表测试集就是真正独立。至少区分以下角色：

| 阶段 | 可做什么 | 不允许做什么 |
|---|---|---|
| 探索训练 | 发掘候选、学习参数和缺失处理 | 偷用未来财务修订与行业名单 |
| 开发验证 | 比较预先列出的候选与参数 | 把验证结果写成最终前瞻业绩 |
| 冻结确认 | 运行选定规则并记录结果 | 用结果继续调参后仍称该期未触碰 |
| 前瞻运行 | 决策时只用当时可知信息，之后才评分 | 反向修改历史预测和失败记录 |

模型族选择、特征加工、初始训练窗口、重训频率、风险与成本假设均属于策略规则。任何规则因查看 OOS 而改变，都需要记录新的研究版本和证据身份。

## 2. Prequential：先预测，后观察，再更新

在第 t 个信号时点，先得到预测 \(\hat y_t\)；随后标签实际形成、被数据系统确认可用，才能把它加入未来训练集。可将可用训练集合写为：

\[
\mathcal D_t =
\{(x_j,y_j):s_j<s_t,\ a_j<s_t\}.
\]

其中 \(s_j\) 是历史信号时刻、\(a_j\) 是经接收与校验后的标签实际可用时刻、\(s_t\) 是本期信号时刻。本章采用**严格早于信号**的保守截止；若另一个研究允许信号之后、决策之前重训，必须单独声明并在代码中采用一致的决策时点门禁。**标签结束不等于标签可用**，来源应记录历史版本。

每一期严格遵守：

~~~text
历史可用标签 → 训练/更新当期模型 → 输出当期预测
    → 等待未来收益及订单结果形成 → 评分并归档
~~~

**允许预先冻结的周期性重训**不等于作弊。但如果在回看后段成绩时才决定“2025 年应该换成另一模型”，就是新的开发行为。只有新的前瞻数据才能提供重新独立的确认。

## 3. 在同一时间线上比较基线和新模型

研究级评估通常以每期 RankIC 序列或组合收益差序列为输入，而非只看一个汇总 IC：

\[
d_t = IC_{\mathrm{new},t} - IC_{\mathrm{baseline},t}.
\]

对 \(\{d_t\}\) 做时间依赖敏感的置信区间、不同市场阶段和不利年份的分层审计。若多次修改模型，应完整登记试验次数、候选假设族、多重比较与最终测试集暴露历史。

**不能把“平均 IC 更高”直接等同于投资净收益更高**。还要考虑 Top-N 单调性、多头超额、换手、未成交、市场冲击、最大回撤及规模约束，明确哪些内容属于下一卷的执行层。

## 4. 三种漂移不应该被混为一谈

| 漂移类型 | 典型问题 | 可观测工具 | 局限 |
|---|---|---|---|
| 特征分布变化 | 因子均值、方差、覆盖改变 | 分层均值、缺失率、PSI、KS | 变了不一定代表信号失效 |
| 关系变化 | 同一个因子预测方向或强度变化 | 分期 IC、回归系数、交互 | 可能是随机波动或结构断裂 |
| 执行环境变化 | 订单延迟、流动性和滑点变化 | 成交/拒单日志、容量与冲击 | 无真实订单时不能确认 |

本轮合成数据在后段人为修改了**一个因子的分布和标签生成关系**。这是有意设计的教材反例，不是发现真实 A 股发生了某次市场结构变化。

教材的 `drift_diagnostic()` 只做开发时期与后续时期的标准化均值差，并明确标记 `posthoc`。它用于**事后解释**，不能回头进入模型选择。若要把漂移指标用于实时调仓或择时，必须另外冻结触发时点、阈值、处理动作和新的前瞻验证。

## 5. 本章的合成时间推演

[实验源码](../../examples/advanced_model_validation_lab.py) 使用 42 个合成周度信号期、每期 12 只人工证券：

| 期次 | 用途 | 模型可以使用的资料 |
|---|---|---|
| 01–20 | 开发训练 | 当时已可供训练的历史标签 |
| 21–30 | 开发验证 | 从 01–20 的合格样本拟合，按验证 IC 选择六个候选之一 |
| 31–42 | 演示性的后续回放 | 每期先从此前已可用标签重训，再预测该期，标签以后才揭晓 |

训练期、验证期和候选集合都在代码中预先固定。后段逐期保存：

- 信号时间与当期训练样本数；
- 最大历史训练标签可用时刻；
- 含训练数据的简短指纹；
- 当期的预测分数（只由当期因子与已训练模型给出）；
- 在标签揭晓后计算的候选与简单因子 RankIC。

**请注意**：代码一次性生成了全部人工标签，然后在函数内部通过时间门禁实现“先预测、后评分”。它能用反例测试证明部分时序隔离正确，**并不等价于独立接收真实市场未来数据**；也不是具备冻结数据源和不可更改交易日志的线上前瞻系统。

## 6. 怎样验证程序没有看未来？

这比只检查 SQL 有没有 `shift(-1)` 更重要。运行：

~~~bash
python examples/advanced_model_validation_lab.py --json
python -m unittest discover -s tests -p "test_advanced_model_validation_lab.py" -v
~~~

这里有两种关键的**反事实程序测试**：

1. **改变全部后段收益**，开发期的模型选择结果必须完全相同；
2. **改变当前与未来标签**，当前预测分数、训练样本指纹不允许改变；但下一期合法重训后，预测可以因为已知的历史标签更新而改变。

同时检查每期最后一个训练标签的可用时间必须严格早于信号时刻。单测还覆盖重复日期/证券、时间无偏移、晚到特征、非有限值与未授权模型候选。

测试通过只代表已经覆盖到的**代码时间语义**成立，不能证明历史 PIT 输入真实、没有遗漏字段或不再存在其它信息泄漏。

## 7. 漂移监控与策略治理

真实项目建议保存两种不同日志：

**决策前日志**：特征覆盖、截面分布、数据是否延迟、当前模型与重训版本、是否触发风控、下单资格。这些必须只使用当时已知信息。

**决策后日志**：收益标签、RankIC、组合净值、交易成本、未成交、异常与模型失效复盘。只有事前定义的重训和监控规则允许把决策后信息带入下一次决策。

建议把停止规则与增量假设一起写入研究合同：若数据不可用、持续超出冻结的风险边界、执行系统异常或证据不足，就暂停而不是修改报表。这些阈值应按研究目标设定，不能声称一个通用 IC 值能决定所有策略的生死。

## 8. 习题及核对

**题 A：** 在后段观察到 Ridge 表现更好，于是把原选定的 pairwise 换成 Ridge，仍报告原后段为最终 OOS，是否合适？

答：不合适。这段已经承担选择模型的职责，应降级为开发或探索证据，新的选择需独立确认。

**题 B：** 已经冻结“每周按当时已知标签重新训练”，后段使用上一周刚形成且已入库的标签，这算未来数据泄漏吗？

答：不算，前提是其 `label_available_at` 早于本周信号，并保存实际版本和重训规则。若标签尚未可用则必须排除。

**题 C：** 特征均值向上漂移，是否意味着 RankIC 必然降低？

答：不必然。输入分布变化与预测关系变化是不同问题，需分别检验。

**题 D：** 正的验证 IC 差值，可以拿来宣布多因子策略在真实市场能盈利吗？

答：不能。还需要独立的真实时间样本、统计不确定性、组合成本和执行证据。
