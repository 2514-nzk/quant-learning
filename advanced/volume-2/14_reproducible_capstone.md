# 第二卷 · 14｜可复现研究工程与综合项目

有人把一张从左下角笔直冲向右上角的净值截图发给你，宣称年化 35%、最大回撤不到 5%。**只凭这张图，你能查出它到底有没有作弊吗？**

查不出来。没有历史股票池快照、没有因子版本、没有参数试错次数、没有拒单和现金流水，你根本无从判断这条曲线靠的是真本事，还是未来函数、幸存者偏差和“理想零成本成交”堆出来的海市蜃楼。

这是第二卷的收官章。走完前面 13 章，我们把所有零件拼回一台完整的机器，只立住一条核心标准：**好的量化研究，不是交出一张最漂亮的图，而是交出一份让陌生第三方能够从头复算、逐关挑刺、并且写明“允许失败”的研究包。**

> **先分清两件事**：**计算可复现性**（同一份代码跑两遍结果一模一样）≠ **研究结论可信**（拿一份有幸存者偏差的脏数据，跑一万遍照样一模一样，但它依然是错的）。

## 1. 一份经得起核查的研究包，里面该装什么？

别再把成果保存成 `最终最终版_v3.csv`。一份最低合格的研究交付目录长这样：

~~~text
study/
  contract.json          # 研究假设、样本边界、时间门禁与认输条件
  data_manifest.json     # 数据来源、授权、历史版本、缺失统计与 SHA-256
  features_and_labels/   # PIT 规则、因子公式、标签结束与可用时刻
  validation/            # 开发期、验证选型、模型版本与测试集暴露历史
  portfolio_targets/     # 风险协方差、目标权重与全部硬约束
  order_ledger/          # 委托意图、实际成交、未成交/拒单与现金流水
  evidence/              # 不确定性区间、敏感性、反例与停机规则
  report.json            # 输入/配置/代码/报告四重指纹与可复算摘要
  reproduce.md           # 运行环境、复现命令与明确未覆盖的局限
~~~

三条铁律记住就行：**保留所有失败和拒单**（不删不利交易）；**配置一改就升版本号**（不覆盖旧产物）；**严守数据版权边界**（受限行情与个人交易记录留在本地，绝不传到公开仓库）。

### 1.1 把三条数据轨道分干净，不混账交付

在本教材和你的日常研究里，不同来源的数据各自只能证明它分内的事，绝不能混成一张表：

| 数据轨道 | 它能帮你验证什么 | 它绝不能证明什么 |
|---|---|---|
| **真实四股固定快照** | 复算真实价格、除息差额、手算公式与小样本敏感性 | 全市场 PIT、无幸存者偏差、独立 OOS |
| **本地大截面日线观察** | 检验大样本覆盖率、复权对照、共同日期与跨年结构 | 未核验成分历史前的无偏差母体、或真实盘口成交 |
| **合成多期面板** | 严测时间门禁、模型隔离、风险约束与账本状态机 | 真实 A 股市场规律或实盘盈利能力 |

如果你在自己电脑上拿合法取得的本地日线 CSV/Parquet 跑大截面研究（比如用第 08 章的 [cross_section_daily_research.py](../../examples/cross_section_daily_research.py)），程序采用两遍扫描只保留所需价格端点并输出文件哈希——既能本地深度验证方法，又无需把私有大表搬进公开仓库。但要记住，几万行截面观测依然只是少数几个日期组，不能当成几万个独立时间样本。

## 2. 给研究做总验收：七道证据关卡（G0–G6）

任何一份量化研究报告交上来，都可以按这七道关卡从上往下逐一打钩——**前面哪一关没过，后面说得再天花乱坠也要降级**：

| 关卡 | 要回答的核心问题 | 没通过时怎么写结论 |
|---|---|---|
| **G0 来源与权限** | 历史数据能否合法取得、溯源并重建？ | 不宣称真实市场有效性 |
| **G1 PIT 与标签** | 特征、行业、财务与标签是否全部严守时点？ | 立刻暂停并审计泄漏 |
| **G2 基线与选择** | 是否在同口径下打败了事先冻结的简单基线？ | 降级为探索性线索 |
| **G3 严格 OOS** | 是否有真正未触碰的充分样本外证据？ | 诚实写明“证据不足” |
| **G4 组合与风险** | 单股、行业、现金、换手与容量是否达标？ | 记录偏差并压缩风险暴露 |
| **G5 订单与净值** | 拒单、税费、实际持仓与 NAV 能否独立对平？ | 禁止发布净收益结论 |
| **G6 部署与治理** | 监控、告警、回滚与停机条件是否齐全？ | 仅限研究或纸面观察 |

对照这七关诚实评估一下本卷当前的教学工程位置：合成实验覆盖了 G1、G4、G5 中的核心程序逻辑与反例测试；而真实全市场 PIT、独立市场 OOS、L2 盘口容量和生产风控尚未接入——**“单元测试全绿”证明的是程序没写错，不是策略能赚钱**。

## 3. 四重指纹：为什么不能只有一个汇总数字？

怎么确保一个月后你重跑出来的报告，真的和今天一模一样？本章的 [合成综合实验](../../examples/advanced_portfolio_execution_lab.py) 在输出报告里打上了四枚 SHA-256 指纹：

- `config_sha256`：研究参数按固定键排序后的指纹；
- `input_sha256`：完整输入市场与信号数据的指纹；
- `code_sha256`：实验脚本源码内容的指纹；
- `report_sha256`：整份输出报告（扣除该字段自身）的指纹。

同时用 `--output` 写出文件时，程序**拒绝覆盖已有文件**，逼着你给每一轮改动起新版本号，把历史试错原封不动留下来。

### 第三方独立复核八步清单

拿到任何一份研究报告时，按下面八步逐项戳一遍，90% 的水分都会现出原形：

1. 用每笔订单的成交额、佣金和税费，独立重算期末现金；
2. 用每日实际持股和收盘价，独立重算整条 NAV 曲线；
3. 故意篡改未来某天行情，确认此前的选股和权重纹丝不动；
4. 试着同日买入并卖出，确认 T+1 拒单生效；
5. 触发买阻挡、卖阻挡和停牌，确认拒单原因全部留在账本里；
6. 故意改坏一行现金或净值，确认审计脚本能当场报警失败；
7. 核对现金、等权与优化分支是否跑在完全相同的执行成本口径上；
8. 核查每份报告的证据等级，确认没有把教学或探索结果夸大成实盘结论。

## 5. 练习与自检

1. 用今天的存活股票池跑回测，换三台电脑跑出的净值小数点后六位都一模一样，能说明它是严格 PIT 研究吗？
2. 账本核对发现 1 元未解释差额，能不能在最终报告里四舍五入藏起来？
3. 本章合成实验里，优化分支的净值跑赢了等权分支，能不能直接拿这套参数上真钱？

1. **答：不能。** 可复现只能证明程序确定性运行，修复不了幸存者偏差和未来修订污染。
2. **答：不能。** 必须查清差异来源、定死精度规则，修不好就触发停止条件，绝不掩盖账本裂痕。
3. **答：不能。** 合成价格和简化执行只用来验收算法逻辑，不能外推到真实 A 股市场。

### 质量核对｜哈希完全一致，研究就一定通过验收了吗？

用同一份合成数据跑两份报告，第二份只改了手续费参数。**问：两份报告的指纹应该怎样变化？反过来，如果两份报告跑出完全相同的四重哈希，能证明研究结论有效吗？**

**答**：修改手续费参数后，必须产生并保存**不同的配置指纹与报告指纹**，绝不能改了结论却复用旧指纹。反过来，两次重跑哈希完全一致，也只证明**输入与计算严格复现**，无法证明数据在历史当时真实可得，更不能把合成回测升格为真实 OOS——牢记第二卷最后一句话：**可复算，不等于研究有效。**
