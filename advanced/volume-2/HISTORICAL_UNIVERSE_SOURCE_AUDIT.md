## 1. 不再只有四只教学股票：本地找到了什么？

必须区分 **GitHub 公开教学样本** 与 **研究电脑上的只读私有数据源**：

| 数据集与证据 | 已核实范围 | 可宣称的事情 |
|---|---|---|
| GitHub 四股 AKShare CSV | 4 只，2024 年 117 个共同已观察日期，合计 468 根日线 | 教学样本文件完整和已公开的描述性算术可复核 |
| 本地 XC/Tushare 派生的 `all_a_membership` | **2010-01-04 至 2026-08-03**，17 个年份分区、**14,536,198 条历史证券日** | 已存在覆盖多年的**历史成员候选数据集**，并有冻结清单及状态字段 |
| 其中 2024 年分区 | **1,296,795 条证券日**、242 个**源审计登记的**开放交易日 | 可以审查此分区的证券成员、报价缺失与状态，不可声称全市场分母经独立权威认证 |
| 其中 2025 年分区 | **1,317,342 条证券日** | 已有次年分区；本节未对其行情完整性做同等级逐字段审计 |

这份 `all_a_membership` 由本地 `factor_platform/universe/historical_all_a.py` 构造，来源标记为 `xc_tushare`，快照 ID 为 `ds_all_a_membership_2c151d73c617cf181f0d95f6`；源清单记录构建时点为 **2026-08-04 12:38:19**。**这意味着“2026 年生成的历史重建快照”，并不自动证明 2024 年每个公告、交易状态、行业或财务版本在当时决策截止前可得。**

2024 年的冻结 Parquet 分区文件 SHA-256 为：

~~~text
11eb9645ef8f6e9b420f24c464e9fd9511503e593a6bc17cafcd179b7e386c34
~~~

本轮机器学习只读 MCP 对该实际文件执行 SHA-256，比对源 manifest **匹配**；分区条数来自 Parquet footer，分组与具体日期统计来自 Parquet 聚合，而不是手工估计。所有可公开汇总保存在 [聚合证据 JSON](local_all_a_2024_aggregate.json)。

## 2. 真实失败案例：历史成员存在，却没有行情

对 2024 年全分区按 `exchange × has_daily_quote` 聚合，结果如下：

| 交易所 | 有日线报价的证券日 | 无日线报价的证券日 | 历史成员证券日 |
|---|---:|---:|---:|
| 沪市 SH | 548,475 | 16 | 548,491 |
| 深市 SZ | 687,805 | 36 | 687,841 |
| 北交所 BJ | **0** | **60,463** | **60,463** |
| **合计** | **1,236,280** | **60,515** | **1,296,795** |

这里的“无报价”是这份**冻结候选数据集**的 `has_daily_quote=false`，**不意味着北交所在 2024 年没有真实成交，也不代表其它本地数据源没有北交所价格**。更不能把这 60,463 行当作零收益。

从一日截面看，**2024-06-21**：

- 历史成员 **5,365 只**，其中 SH 2,268、SZ 2,848、BJ 249；
- 有日线报价 **5,116**、缺报价 **249**，缺口**恰好全部为 BJ**；
- `is_trading=true` **5,095**、`false` **21**、`NULL/UNKNOWN` **249**；
- `is_st=true` **152**、`false` **5,213**。

这说明至少存在两条独立门禁：**成员是否在历史母体中**，以及**该成员当时有无可用价格**。`is_trading=NULL` 不是“可交易”，也不是“停牌”，而是“不能从这份数据确定”。2024 年分区的 `(trade_date, code)` 重复主键组数为 **0**，但这不能修复价格缺口。

另一个反例：`000005.SZ` 在 2024-01-02 的历史成员截面中保留，当时 `is_st=true`、有报价；快照中 `delist_date=2024-04-26`，2024-06-21 已不再进入成员截面。这证明数据集**不是简单只留下 2026 年仍存活的股票**，但仍不足以独立证明所有历史退市记录和身份都完整。

## 2A. 对“缺报价”的独立核验：不该怪罪停牌或未上市

对 2024 年冻结 Parquet **逐条读取**沪深交易所的全部 `has_daily_quote=false` 记录，结果比泛称“数据缺失”更精确：

| 条目 | 行数 | 本地可证实的原因分类 |
|---|---:|---|
| SH 无价 | 16 | **16/16 的 `trade_date == delist_date`** |
| SZ 无价 | 36 | **36/36 的 `trade_date == delist_date`** |
| SH/SZ 合计 | **52** | **52/52 均为摘牌日期边界记录**；无一条 `has_suspend_record=true` |
| BJ 无价 | **60,463** | 不能用“摘牌/停牌”解释；主要疑点是**行情源覆盖、证券新旧代码及联表方式** |

为何沪深在摘牌当日还能出现在候选母体？本地构建器在成员联结中使用：

~~~sql
trade_date >= effective_list_date
AND (delist_date IS NULL OR trade_date <= delist_date)
~~~

这是包含摘牌日的闭区间规则。在某些交易类退市案例里，**摘牌当天已经不能交易**，于是成员行仍在，而 `daily` 没有同日 K 线。以 ST 星源（000005）为例，[深交所 2024-04-25 公告](https://disc.static.szse.cn/disc/disk03/finalpage/2024-04-25/b8989912-ffa8-42a1-9f29-915e833bbb84.PDF) 确认 2024-04-26 摘牌；[上交所关于华仪的终止上市决定](https://www.sse.com.cn/disclosure/announcement/listing/stock/c/c_20240109_92503416.shtml) 及公告确认 2024-01-16 摘牌、不进入退市整理期。这些例子支持**摘牌日起不再有正常上市股票交易报价**，而不是“日线下载失败”。

**不能简单把全部 52 行删掉**：`delist_date` 的语义需要逐证券核对，尤其对曾进入退市整理期的股票应区分“最后实际交易日”和“正式摘牌日”。专业数据合同建议分别保留 `last_trading_date`、`delist_effective_date`、`security_exists`、`exchange_tradable`，实际回测按后者处理。这次只核实了 52 行均落在快照摘牌日，并用部分交易所公告做了交叉印证；尚未逐个完成全部 52 条的交易所公告对照。

北交所需要**两项不同的修复**：

1. **2024 年旧代码与后来统一的 920 代码**。构建器强制用 `920xxx.BJ` 规范证券代码创建成员，同时用 `daily.ts_code = member.code` 直接关联，没有按历史生效日转换代码。北交所 2025-10-09 才完成存量公司统一切换，故这对 2024 年使用 `43/83/87` 代码的股票可能联不上。例：云星宇 **2024-06-21 以 `873806`** 交易，但如今规范代码为 `920806`。[北交所代码切换公告](https://dataclouds.cninfo.com.cn/sjother/regulatory/2024/20241213/d7cfc96e816541629e69b0e257d98dbe.pdf)、[新旧代码对应表](https://www.cgws.com/cczq/ggdt/gsgg/202509/t20250929_321701.html)。
2. **不能只归因于代码映射**。2024-06-21 已经直接使用 `920002` 的万达轴承，在当前冻结 Parquet 仍被标记无价；但是当日 [《证券时报》北交所成交明细](https://www.stcn.com/article/detail/1237416.html) 明确记录 **`920002` 万达轴承收盘 52.01 元**、`873806` 云星宇 9.44 元、`873001` 纬达光电 8.18 元；当日北交所总成交额 **39.90 亿元**。这实证排除了“2024 年北交所没有交易”和“问题完全因为旧代码”两种解释，意味着还需要核对源 `daily` 表究竟有没有覆盖北交所行情、数据接口是否过滤交易所、规范映射是否匹配。

**AKShare 历史行情复核已经实际执行**：[2026-11-13 GitHub Actions 独立任务](https://github.com/2514-nzk/quant-learning/actions/runs/43378034226) 使用 `stock_zh_a_hist(period="daily",start_date="20240621",end_date="20240621",adjust="")` 查询三个案例，均返回明确的当日价格，且**全部与 2024 年 6 月 21 日《证券时报》的收盘价一致**：

| 2024 年真实交易代码 | AKShare 本次可返回历史价格的代码 | 2024-06-21 不复权收盘 | 旧代码在本次 AKShare 查询中 |
|---|---|---:|---|
| 云星宇 `873806` | `920806` | **9.44 元** | 旧码无当日记录 |
| 纬达光电 `873001` | `920001` | **8.18 元** | 旧码无当日记录 |
| 万达轴承 `920002` | `920002` | **52.01 元** | 新旧同码 |

这说明 **AKShare 当前接口有能力按规范新代码展示旧代码时期的历史交易价格**，也证明至少三个本地未关联成功的北交所证券-日期存在实际行情。但**尚未直接查询本地源 DuckDB 的 `daily` 表**，所以不能断定这三只的行是被代码映射弄丢、原表没下载、还是组合原因。需要按 `source_code`、`historical_code`、`security_id` 与交易日期逐层做 anti-join 查明。

为便于在任意有网络的研究机复核，提供 [AKShare 历史日线核验脚本](../../examples/advanced_quote_cause_audit.py)：

~~~bash
python examples/advanced_quote_cause_audit.py --json
python -m unittest discover -s tests -p "test_advanced_quote_cause_audit.py" -v

# 下面两条需在有网络和 AKShare 的环境主动执行
python -m pip install akshare
python examples/advanced_quote_cause_audit.py --akshare --json
~~~

脚本严格按日期查询 2024-06-21，并分别尝试历史代码和规范代码，只有返回当天明确的行情才算外部样本对照；本次已使用云端运行器实际复验三个报价，但未把这个结论推广到全市场；**API 空返回不证明停牌、退市或没有交易**。AKShare 的 `stock_zh_a_hist` 是沪深京 A 股历史行情接口，数据由第三方行情提供方提供，也不是权威历史 PIT 证明。文档见 [AKShare 历史行情接口说明](https://akshare-hh.readthedocs.io/en/latest/data/stock/stock.html)。

因此目前最准确的结论是：**沪深 52 行属于候选股票池的摘牌日端点问题；北交所 60,463 行是源行情覆盖/历史代码映射/联表口径尚未修复的标记，绝不等于真实市场缺价。**

## 3. 历史母表有了，源审计仍为何不能全部通过？

冻结快照内置的构建审计明确记录了下列风险：

| 检查项 | 源清单记录 | 处理原则 |
|---|---:|---|
| `stock_basic` 行数 | **10,000** | 恰好达到采集接口单次上限，**存在截断风险** |
| 严格六位 A 股交易代码记录 | **6,681** | 和 10,000 条原始记录不是同一分母 |
| 严格代码缺 `list_date` | **477** | 构建中显式排除，可能造成成员缺口 |
| 北交所企业缺规范 `920xxx.BJ` 映射 | **464** | 不能任意把旧代码作为另一家企业或默默补映射 |
| `daily_basic` 重复主键组 | **17,079** | 不得不审计就 `DROP DUPLICATES` |
| 其中存在不同内容冲突的重复组 | **9** | 需要独立的来源与生效口径核对 |
| 2024 `(trade_date, code)` 重复 | **0** | 只证明该分区键唯一，不证明行内字段一定正确 |

原构建程序还审计 `previous_name`、`suspend`、`stk_limit` 等历史信息，并在缺行情或状态冲突时保留质量标记。快照总体是**可研究的候选历史母体**，而不是“不含缺口的权威全市场总表”。

已存在其他候选层，**但本轮未获准直接查询数据库内全部实时表**：

- 本地数据目录快照登记 `index_member_history`（SW2021）**23,219** 行、`index_member_history_2014` **22,148** 行；版本体系须依历史生效日切换。
- 申万官网历史归属事件表 `sw_industry_assignment_events_official` 的目录快照登记 **12,929** 行，保留官网 XLS 文件 SHA、计入时间与更新时间；**更新时间不是首次历史公开可得时刻**。
- 2026-11-02 的同花顺十年财务回补 manifest：以当时**存活**股票为目标 **5,579** 只，完成 **2,242**、待补 **3,337**、返回报表 **253,790** 条；已因 HTTP 429 暂停，且不含所有历史退市证券。这是旧批次状态，不是现在完整度的断言。
- QMT 财务 PIT 事件及 `available_date` 字段有本地设计/目录证据；逐条披露与历史接收时间仍需独立核验。

**本节不能用上述目录记录的数量去计算 2024 年真正全市场的行业或财务 PIT 覆盖率**。目录行数并不是当前可用的“已验证历史分母”。

## 4. 我们能实际复算到哪一级？

公开仓库新增 [机器可读汇总](local_all_a_2024_aggregate.json)、[汇总一致性核验脚本](../../examples/advanced_local_snapshot_audit.py) 和 [异常测试](../../tests/test_advanced_local_snapshot_audit.py)。**JSON 不包含任何单证券行情行、库文件或供应商原始材料。**

在公开 GitHub 克隆中（无需真实私有数据）：

~~~bash
python examples/advanced_local_snapshot_audit.py --json
python -m unittest discover -s tests -p "test_advanced_local_snapshot_audit.py" -v
~~~

这两条命令验证**公开聚合之间的算术一致性和证据等级**，不可能替代对本地源文件的读取。拥有本地原始分区且安装 `duckdb` 的研究者可以执行：

~~~bash
python examples/advanced_local_snapshot_audit.py --verify-parquet "/本地/私有目录/2024.parquet" --json
~~~

仅在用户本地执行：先比对真实 Parquet SHA-256，再按交易所重新计数 `has_daily_quote`，检测 `(trade_date,code)` 重复；哈希或统计不一致会拒绝。**不会访问网络或将私有数据上传**。外部读者拿不到源数据时，只能核对汇总内部一致性，不能独立复现全部原始统计；此限制需要保留。

本卷原有的 [四股真实价格审计](REAL_DATA_EVIDENCE_REVIEW.md) 和 [合成时点输入合同](../../examples/advanced_pit_intake_lab.py)、[合成参考母体实验](../../examples/advanced_universe_coverage_lab.py) 仍保留，用于对照教学层、真实历史来源盘点和严格 PIT 之间的不同证据等级。

## 5. 数据选择问题如何改变第 06–08 章？

任何研究日应先冻结并报告三种集合：

\[
U_t^{membership}=\{\text{已知历史成员}\},\qquad
U_t^{quote}=\{\text{截止时可用价格}\},\qquad
U_t^{factor}=\{\text{截止时因子可用}\}.
\]

其中 `U_quote` 的历史可用性需要可信的公告、来源/接收时间证据；本轮实际报告的是**2026 年回溯快照上的报价非空状态**，不可自动升级为真实 `available_at`。对 **60,463 条北交所在本候选快照中未关联到报价的证券日**，绝不能简单填零、假定停牌、或者先删除再把得到的 IC 称为全 A 股截面有效性。

教学时先冻结“全市场 A 股（SH/SZ/BJ）”和“只研究 SH/SZ”两个**明确不同的目标范围**，对每个目标单独报告缺失比例与证券状态。之后才可以设计标签、Purge、因子中性化与模型训练；没有真实可用的入场/退出价格时，不能生成可交易收益标签。

## 6. 结论与停止条件

**本轮新证据**：本地确有跨 17 年、1,453 万条历史证券日的候选母体；2024 年分区哈希通过，证实当前股票池**北交所报价关联存在系统性失败**，并能列举后续需要修复的源头问题。

**没有被本轮证明**：当年首次公开/入库时间、权威完整市场分母、历史全部退市身份、公司行为和可成交收益；也没有运行真实因子有效性或独立 OOS 检验。

如果后续无法核实北交所历史报价的代码映射与源表覆盖、`stock_basic` 截断和行业/财务披露版本，研究必须停留在受限的来源审计或明确限定的沪深范围，不能声称完成“全 A 股 PIT Alpha”。
