# 深度专题 B｜机器学习训练、验证与真实增量

这一篇接在第 11–14 章之后。目标不是让你盲目增加复杂模型，而是能独立回答：**为什么一个模型训练分数更高，样本外排序却可能更差？模型到底有没有超过简单因子？**

本章有两种运行方式：先用**纯标准库**阅读已冻结的模型实验记录，再安装原项目依赖实际重训。两者不是同一件事，阅读参考报告不等于重新训练过模型。

> 本书的 60 期、240 条股票行是人工教学样本。无论预测成绩多好，都不能代替真实 A 股样本外回测。R47–R60 的原测试结果已经公开在教材中，今后基于它设计的新模型不能再把这段称作“完全未看过的测试集”。


## 先给第一次读专题的人：模型不是猜涨跌的神秘机器

把模型想象成一个会给 A、B 打分的助手。你给它两列以前看得到的分数：

| 股票 | 最近走势分 | 盈利质量分 |
|---|---:|---:|
| A | 1.0 | 0.5 |
| B | 0.5 | 1.0 |

假设这次规定走势占 60%、质量占 40%，A 得 **0.8**，B 得 **0.7**，所以 A 排前。机器学习做的事，只是**从过去的数据中学出权重或更复杂的打分规则**，然后去评价它在新日期是否仍然有用。

三个模型可以先这样区分：

| 名称 | 用最普通的话理解 |
|---|---|
| Ridge | 给各列打分乘权重，同时不让权重太极端 |
| 随机森林 | 很多棵会问“如果……那么……”的树一起给结果 |
| LightGBM | 一棵接一棵修正前面的预测，而不是一次学完 |

**最重要的不是名字，而是公平考试。** 用过去题目训练、用较新的题目选方法、用完全没参与选择的题目检查。如果已经看过最后考试，再改模型，就不能说这是第一次考试。

下面第 2–4 节有公式，先看文字和表格即可；等你会复算最简单的例子，再回来读公式和调参。


## 1. 模型到底在预测什么？

本书的每期未来标签不是下一期收益率的绝对数值，而是四只股票未来收益的**横截面百分位名次**。例如 R01 从低到高为 D/B/C/A，对应：

| 股票 | 未来收益 | 回归目标 label_rank |
|---|---:|---:|
| D | -2% | 0.25 |
| B | 1% | 0.50 |
| C | 3% | 0.75 |
| A | 5% | 1.00 |

模型输入只有决策时可知的 mom_5、ep、roe 三列。输出是一个**用于排序的预测分数**，并非“预计涨幅 80%”“上涨概率 80%”或交易指令。分数与真实收益之间，还隔着 Top-N 选择、权重、成交、成本和风险。

为什么要分开目标？因为最小化回归预测误差、优化全截面 RankIC 和最大化真实组合净收益，是三个不同任务。一项训练目标有改善，未必意味着另外两个目标也改善。

## 2. Ridge：从加权评分到正则化

最简单的线性预测器：

~~~text
预测分数 ŷ_i = b + w₁·z_动量 + w₂·z_EP + w₃·z_ROE
~~~

这里的 z 是标准化后的输入。通常先在训练数据估计均值与标准差：

~~~text
标准化 z_i,j = (x_i,j − 训练均值_j) / 训练标准差_j
~~~

验证和测试必须继续使用训练得到的均值与标准差，不能拿整份 60 期计算“全局均值”。如果某一列的训练方差为 0，还需要定义固定的安全处理；不能因除以 0 而产生无穷大。

Ridge 的基本形式可以写成：

~~~text
min_{w,b}  Σ_i (y_i − b − x_i·w)² + α × Σ_j w_j²
~~~

前一项要贴近训练标签，后一项限制系数过大。通常对截距 b 不施加相同的 L2 惩罚。不同软件对损失缩放和 alpha 口径可能不同，比较时应固定实现。

**为什么先标准化？** 如果 EP 用 0.05 表示，而另一列用 50 表示，相同经济变化对应的系数会因单位改变。Ridge 直接惩罚系数大小；如果单位不统一，正则化的比较就可能混入单位偏差。

本书代码用 scikit-learn 的 Pipeline 把变换和模型绑在一起：

~~~python
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Ridge

model = make_pipeline(StandardScaler(), Ridge(alpha=0.1))
model.fit(train[["mom_5", "ep", "roe"]], train["label_rank"])
validation_score = model.predict(validation[["mom_5", "ep", "roe"]])
~~~

这段代码假定 train/validation 已按时间和标签边界切好，不能独立运行。完整可运行流程在 examples/story_research.py。

## 3. 决策树：为什么训练越好反而可能越差？

回到 R01，四个未来名次标签为 1.00、0.50、0.75、0.25。若全都预测平均数 0.625，误差平方和为：

~~~text
(1−0.625)² + (0.5−0.625)² + (0.75−0.625)² + (0.25−0.625)² = 0.3125
~~~

若按“过去五日涨幅是否至少 4%”切为 A/C 与 B/D 两组，分别预测组内均值 0.875 和 0.375，误差平方和降到 **0.0625**。

这只能证明在**这四条训练样本**里切分更贴近标签。若继续把每个样本切到单独叶子，训练误差还能进一步下降，却可能只是记住偶然噪声。

树模型的四个常见容量控制：

| 设定 | 数学/程序意义 | 过大或过小的风险 |
|---|---|---|
| max_depth | 最多走多少次分裂 | 太深可能记住训练细节 |
| min_samples_leaf | 每个叶子最少训练样本 | 太小会对噪声敏感 |
| max_features | 每次分裂可考虑多少输入 | 改变树间差异与拟合能力 |
| n_estimators | 森林包含多少棵树 | 过少不稳定，增多不保证样本外改善 |

随机森林平均多棵有随机差异的树，往往可以降低单树方差，但**不能修复数据泄漏、错误标签或市场结构变化**。袋外（OOB）诊断也不自动等于未来时间样本外评价。

## 4. Boosting 与 LightGBM：逐步修错不等于越多越好

Boosting 将多轮小模型加到已有预测上。对平方误差目标，新一轮模型大致尝试拟合当前残差，预测更新可示意为：

~~~text
F_m(x) = F_(m−1)(x) + η × h_m(x)
~~~

其中 η 是学习率，h_m 是新树的输出。实际 LightGBM 有自己的树生长、分桶、正则化和优化实现；这条式子只说明一般加法更新思想。

在本书固定实验中，学习率为 0.05。固定候选树数 15、50、150 的训练与验证结果：

| 树数 | 训练平均 RankIC | 验证平均 RankIC |
|---:|---:|---:|
| 15 | 0.5943 | 0.4381 |
| 50 | 0.6500 | 0.3800 |
| 150 | 0.7889 | 0.2200 |

加树之后训练指标上升，验证指标却下降。**这不是 LightGBM 普遍无效的证明**，只是固定教学样本中的容量对照。

原脚本还设置最多 200 轮，以验证集的 L2 损失早停，记录 best_iteration=14，然后在训练+验证数据重训 14 轮模型，最后评估测试集。要注意：

- 这里**早停监控 L2**，不是表格中的 RankIC；
- 14 轮由验证损失决定，不等于先挑 15/50/150 三个 RankIC 候选中的最高者；
- 训练+验证重训以后，原验证集已经参与模型拟合，不能再作为新证据；
- 测试只能在设计已经固定以后用于最终描述，不能参与“该停几轮”的决定。

## 5. 用已保存的记录核对选参过程

先不安装任何第三方 Python 包，运行：

~~~powershell
python examples/model_selection_audit.py
python examples/model_selection_audit.py --json
~~~

脚本读取 data/story/model_results.json，从试验表里按**验证 RankIC**核对 Ridge 和随机森林的候选选择。Ridge 的候选 alpha 为 0.1、1、10；前两者验证平均 RankIC 同为 0.40，按原先候选顺序保留 0.1。森林深度 2、4、不限制，分别得到验证 0.38、0.42、0.26，保留深度 4。

LightGBM 的 14 轮是另一套按验证 L2 的早停结果。脚本核对记录的轮数范围，但不假装能由三个 RankIC 行倒推完整的逐轮验证曲线。

然后重新训练一次（需要安装 requirements.txt 中的 NumPy、pandas、scikit-learn、LightGBM）：

~~~powershell
pip install -r requirements.txt
python examples/story_research.py --models --output outputs/story/my_model_report.json
python examples/model_selection_audit.py --report outputs/story/my_model_report.json
~~~

**重要区别：** model_selection_audit.py 只检查一份保存的报告内部是否自洽，不能证明作者此前没有偷看测试，也不能凭 JSON 独立验证模型确实训练过。真正的审计仍需要源代码、历史试验日志、环境和在报告生成之前冻结的协议。

## 6. 训练、验证、测试如何各司其职？

固定教学日历按完整“期”划分：

| 样本 | 用途 | 包含股票行数 |
|---|---|---:|
| R01–R36 | 拟合模型与预处理参数 | 144 |
| R37–R46 | 选 alpha、深度及早停 | 40 |
| R47–R60 | 固定后的描述性测试 | 56 |

但独立的**市场时间点只有 36/10/14 期**。即使每期有四只股票，也不能把验证集误当成 40 个独立市场日。真实 A 股还存在同一天的共同冲击及相邻持有期重叠。

原标签边界合格：R36 的标签在 D221 结束，R37 在 D222 决策；R46 的标签 D281 结束，R47 在 D282 决策。如果标签期限改长，必须重新核对并执行 Purge，而不是认为所有“五日收益”天然不重叠。

可用下面的对照核查你的代码：

~~~text
只在 train 上 fit：训练/验证调参阶段
只在 validation 上选择参数或早停：最终设置冻结前
train+validation 重新 fit：使用冻结后的参数
test 只做一次描述：不能参与修改参数、特征、交易规则
~~~

由于原教材已经公开了测试结果，**今天新提出的模型或新因子不能在这 14 期上再声称全新独立确认**。这正是学会“样本外”以后最重要的纪律之一。

## 7. 怎样证明复杂模型真正有“增量”？

先让所有模型拥有同一股票池、同一标签、同一验证协议、同一成本、同一起始资金。至少与以下基线比较：

1. 原始动量因子；
2. 三因子横截面排名等权；
3. Ridge；
4. 随机森林；
5. LightGBM。

在教材已公布的 R47–R60 中：

| 模型/评分 | 平均 RankIC | 成本后纸面期末金额 |
|---|---:|---:|
| 动量 | 0.4857 | 10,793.05 元 |
| 三因子平均 | 0.4545 | 10,204.92 元 |
| Ridge | 0.3000 | 10,578.83 元 |
| 随机森林 | 0.1286 | 10,361.94 元 |
| LightGBM | 0.1429 | 10,407.84 元 |

这张表只显示**这套固定人工数据中复杂模型没有超过动量基线**。它不意味着动量在真实 A 股一定有效，也不意味着 LightGBM 在真实市场一定较差。

增加一项特征时，最好有清楚的**增量检验**：在相同样本上保留全部特征与删除一个特征后重训，比较验证表现、真实后续样本外排序、Top-N 重合率、换手及成本后净收益。

相关输入会造成系数和特征重要性的归因不稳定；不能把相关特征之间的权重挪动理解成经济因果。置换重要性测试“打乱一列后的影响”，删除后重训的消融测试“没有这一列时完整流程的表现”，两者不等价。

## 8. 研究型模型需要记录的诊断

| 研究问题 | 最低证据 | 常见误判 |
|---|---|---|
| 是否学到稳定信号？ | 时间外 IC 和跨时段分布 | 训练 IC 很高就是成功 |
| 是否有增量？ | 同样本、同成本的简单基线和消融 | 只与一个很弱的模型比 |
| 是否能成交？ | 下单时刻、盘口约束与成本 | 直接把预测分数当收益 |
| 是否过度调参？ | 所有试验次数与先验协议 | 只展示最终最优参数 |
| 是否可解释？ | 特征相关性、稳定性、消融 | SHAP 或系数就是因果 |
| 是否可外推？ | 新的时间段或独立数据 | 在已看过的测试上反复重试 |

不要用“一个小 p 值”“一个 ICIR 数字”“一张净值曲线”代替完整诊断。相邻日期的同向收益、市场共同冲击、参数搜索与统计不确定性，都可能使看上去显著的结果不稳定。

## 9. 项目作业与答案核对

**作业 A：为什么 Ridge 要在 Pipeline 里做标准化？**

<details>
<summary>核对</summary>

因为 Ridge 的正则化惩罚依赖系数尺度；如果预处理器单独用全部历史 fit，验证和测试的信息会提前进入转换参数。Pipeline 能让预处理跟随同一个训练 fit，但前提仍是使用正确的时间划分。

</details>

**作业 B：为什么本例 LightGBM 最佳 14 轮，不等于验证 RankIC 表中 15 轮最佳？**

<details>
<summary>核对</summary>

两个过程监控的不是同一目标。14 轮来自逐轮 L2 验证损失的早停；15/50/150 的表汇报的是各固定候选的 RankIC。不能混用指标，之后再用测试选对自己最有利的版本。

</details>

**作业 C：如果读完这张测试表，现在想新加“只在低波动期用模型”的条件，该怎样检验？**

<details>
<summary>核对</summary>

先明确低波动条件是否在信号时刻可知；这是看过测试后提出的新假设，应在新的、未参与设计的未来时期验证。旧 R47–R60 只能作探索，不能重新获得“最终盲测”的资格。

</details>

**最终交付：** ①固定研究协议；②所有候选训练与验证表；③预处理拟合范围与随机种子；④最终测试原始输出；⑤对照基线与特征消融；⑥执行假设和失败案例；⑦重新训练命令、环境与版本。做不到这些时，即使模型输出一个很高的分数，也还不能称为完成研究。
