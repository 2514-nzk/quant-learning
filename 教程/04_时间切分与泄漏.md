# 第 4 章：时间顺序是金融机器学习的硬约束

## 1. 为什么不能随机切分

随机切分会把未来市场状态、同一标签窗口和同一股票的相邻样本混入训练与测试。即使没有显式使用未来字段，也会高估泛化能力。

## 2. 三个数据集的职责

- Train：拟合模型参数和预处理器。
- Validation：选择模型、超参数和停止轮数。
- Test：研究规格冻结后的最终评价。

测试集不是“另一个验证集”。每看一次测试结果并据此修改，测试集就被污染一次。

## 3. 滚动方案

大纲建议过去 3 年训练、6 个月验证、1 个月测试，每月滚动。为了本地演示更快，默认配置缩短为约 2 年训练、3 个月验证、3 个月测试，每 3 个月前移，使各样本外测试窗口连续衔接。理解流程后再把配置改回正式窗口。

```text
[------ Train ------][隔离][Validation][隔离][Test]
                         向前滚动 ->
```

`embargo_days: 5` 在两个边界都隔离 5 日标签。训练集最后一个信号的退出价格不能落入验证期，验证集最后一个信号的退出价格也不能落入测试期。

Purge 与 Embargo 经常混用，但含义不同：Purge 删除标签窗口与后一区间重叠的旧样本；Embargo 在边界后额外留出一段禁止使用的新样本。本项目的固定期限标签用显式空档实现保守隔离。若未来加入可变退出日、财务事件窗口或重叠 cohort，应按每条样本的真实 `entry_date/actual_exit_date` 做事件区间 Purge。

每一折的顺序是：只在 Train 拟合预处理器和候选模型；在 Validation 比较 Ridge alpha、随机森林复杂度并决定 LightGBM 停止轮数；将选定规格在 Train+Validation 上重训；最后只对 Test 预测一次。

## 4. 五类常见泄漏

1. 在全样本上标准化或填补缺失。
2. 用测试期选择特征和参数。
3. 使用当前成分股或当前行业回填历史。
4. 财务数据按报告期而不是公告/可用日对齐。
5. T 日收盘产生预测，却用 T 日收盘成交。

## 练习

复制一次实验，故意使用 `train_test_split(shuffle=True)`，再与滚动样本外结果比较。不要把错误结果当成候选策略；目的是观察泄漏通常如何让指标变漂亮。

## 5. 用具体日期读懂边界

假设标签 horizon 为 5 个交易日，训练信号日最后一天是 2024-03-01：

```text
训练最后信号       03-01
标签可能用到        03-08（T+5）
隔离区              03-04 ～ 03-08
验证最早信号        03-11
```

这里的空档不是为了少用几天数据，而是防止训练样本的未来价格窗口与验证样本靠得太近。当前 `rolling_splits` 用交易日位置而不是自然日做切分，因此周末和节假日不会被误当成交易日。

验证结束后还要再次隔离，才能让验证最后一个标签窗口不触碰测试期：

```text
[Train] [embargo] [Validation] [embargo] [Test]
```

如果标签 horizon 从 5 改成 10，`embargo_days` 也要重新检查。当前配置校验明确要求 `embargo_days >= label.horizon`，这是保守规则；标签期限可变或退出日顺延时，还要按事件区间审计。

## 6. Purge 和 Embargo 的区别

设一条样本的事件区间是 `[signal_date, actual_exit_date]`：

- **Purge**：发现训练事件区间与验证区间重叠时，删除重叠的训练样本；依赖每条样本的真实事件边界。
- **Embargo**：在切分边界之后额外空出一段时间，禁止相邻样本进入下一集合；实现简单但较保守。

固定 T+5 标签时，显式留出 5 个交易日可以近似完成边界隔离；若退出日因停牌顺延、标签期限可变或采用重叠 cohort，就不能只看固定天数，应按事件区间做 Purge。

## 7. 每折训练顺序

```python
for train_dates, validation_dates, test_dates in rolling_splits(...):
    train = sample[sample.trade_date.isin(train_dates)]
    validation = sample[sample.trade_date.isin(validation_dates)]
    test = sample[sample.trade_date.isin(test_dates)]

    # 只用 train 拟合候选模型和预处理器
    # 只用 validation 选 alpha、树复杂度或停止轮数
    # 冻结规格后用 train + validation 重训
    # test 只预测一次并保存
```

当前 `run_research` 会把每折的训练、验证、测试起止日期和选中的参数写入 `metrics.json`。验收时应抽查至少一折，确认选参记录中的验证指标没有变成测试指标。

## 8. 泄漏审计问答

每个实验结束后回答：

1. 特征最晚使用到哪一天？
2. 标签最早从哪一天开始使用未来价格？
3. 标准化、截尾和缺失填充参数在哪个集合上拟合？
4. 股票池是否由当日可知的信息动态生成？
5. 测试结果是否被看过并用于改参数？
6. 组合是否在 T 日收盘价成交？

只要第 5 个问题答案是“是”，就应把这次测试视为探索性结果，重新留出未触碰的数据做最终确认。练习答案需要指出具体哪段未来信息进入了哪一步，并说明如何改成滚动样本外。
