# 第三卷 · 09｜集合竞价、L2 数据与订单流

> **状态：教学正文 v1；证据等级：SYNTHETIC_ONLY；独立的竞价快照、订单生命周期、成交关联、五档盘口和测量审计实验已建立。** 本章使用人工数据验证字段定义与计算，不使用个人研究数据库，不代表真实市场结果，也不证明任何订单流策略有效。

## 本章核心问题

Level-2 数据比普通行情多了哪些可观察信息？集合竞价的虚拟价格和未匹配量应该怎样解释？逐笔委托、逐笔成交和盘口快照如何对应？大单、撤单、主动买卖和订单流失衡到底能测量什么，又有哪些东西根本无法从行情数据中知道？

本章先建立一条底线：

> **行情数据记录的是交易系统向市场发布的报价、委托和成交信息，不是投资者身份、真实意图或账户资金流。**

本章研究对象是交易所 Level-2 行情及其经过授权的数据服务，不把券商终端的 QMT Tick 返回值直接称为交易所原始逐笔数据。QMT 接口返回什么，必须逐字段核对接口版本、数据权限、刷新频率、聚合规则和来源。

## 1. 先把 L1、交易所 L2、供应商数据和 QMT Tick 分开

“Tick”是一个容易引起误解的词。它可能指一笔成交、一次报价更新、一帧快照，也可能只是某个 API 返回的一组字段。**仅凭变量名叫 Tick，无法判断数据粒度。**

| 数据类型 | 通常能观察什么 | 不能自动推出什么 |
|---|---|---|
| Level-1 快照 | 最新成交、累计成交、有限档位报价等基础行情 | 每笔委托的完整生命周期 |
| 交易所 Level-2 | 依交易所产品和许可，可能包含更丰富的盘口档位、逐笔委托、逐笔成交、订单关联等 | 投资者姓名、账户、机构身份、下单动机 |
| 供应商加工数据 | 供应商按自身口径清洗、聚合或计算的字段 | 加工字段等同于交易所原始字段 |
| 券商终端 / QMT Tick API | 具体接口文档承诺返回的行情结构 | 默认等同于交易所原始 L2、完整逐笔委托或完整订单队列 |

以上区别不是“L2 一定能看到所有东西”。例如，上证所信息网络发布的《上海证券交易所 Level-2 产品说明书》2.0.0 版本列出了买卖 10 个价位、最优价位前 50 笔委托队列、逐笔成交和逐笔委托等内容；这描述的是该产品版本的能力，**不能直接外推为深交所、所有供应商或所有券商 API 都提供完全相同的字段**。

尤其要注意：

- 最优价位前 50 笔队列，不等于所有价位、所有订单的完整队列。
- 逐笔成交中的买卖订单关联，不等于知道买卖双方是谁。
- 某些产品有订单编号、通道号或内外盘标志，仍须按具体接口说明理解字段语义。
- 供应商可能重命名、聚合、去重、补发或重建数据；加工后的结果要标明来源和版本。
- 如果 QMT Tick 只返回定时或事件触发的快照，它就不能替代逐笔委托事件流；如果某个 QMT 权限确实提供更丰富的字段，也必须用接口文档和样本核实，而不是靠名称猜测。

**本课程的数据源标签必须至少包含：** **source_vendor**、**source_product**、**api_or_protocol_version**、**venue**、**feed_type**、**entitlement**、**capture_time**、**field_dictionary_version**、**normalization_version**。缺少这些信息时，先做数据审计，不进入策略研究。

## 2. 集合竞价的时钟：先确认什么时候能申报、什么时候不能撤单

截至本章校核日期，沪深交易规则对一般竞价交易股票的主要时段如下：

| 时段 | 竞价阶段 | 研究时要注意什么 |
|---|---|---|
| 09:15–09:20 | 开盘集合竞价 | 可申报；规则允许的撤单窗口 |
| 09:20–09:25 | 开盘集合竞价 | 交易主机不接受竞价撤单申报 |
| 09:25 | 开盘集合撮合 | 形成开盘成交结果 |
| 09:25–09:30 | 开盘后、连续竞价前 | 不要把券商客户端本地接受委托等同于交易所正在撮合 |
| 09:30–11:30 | 上午连续竞价 | 逐笔连续撮合 |
| 13:00–14:57 | 下午连续竞价 | 逐笔连续撮合 |
| 14:57–15:00 | 收盘集合竞价 | 交易主机不接受竞价撤单申报；15:00 形成收盘撮合结果 |

深交所《交易规则（2026 年修订）》第 3.3.1 条明确列出申报时段，并规定 09:20–09:25、14:57–15:00 不接受竞价撤销申报；上交所现行《交易规则（2026 年修订）》也规定了相应的集合竞价时段和撤单限制。上交所 2026 年修订规则自 2026 年 7 月 6 日起施行。

这里有三个容易犯的错误：

1. 把 09:20 之前的虚拟参考价当成最终开盘价。
2. 把 09:20 之后未撤销的申报直接解释成“资金坚定看多/看空”。
3. 忘记收盘集合竞价也有自己的时间门禁，错误地把 14:57 后的数据当作连续竞价。

不同证券品种、板块、停复牌状态和特殊业务可能有附加规定。正式研究必须先确定证券范围，再按对应的现行规则冻结交易日历和时段表，不能把一张时间表不加区分地套用到全部证券。

## 3. 虚拟参考价、匹配量和未匹配量：它们是当时的指示值

集合竞价阶段，行情可能发布：

- **虚拟参考价格**：按照当时已进入撮合系统的申报计算出的指示价格；
- **虚拟匹配量**：按当时申报可匹配的数量；
- **虚拟未匹配量**：在该指示价格下尚未匹配的买方或卖方数量。

它们是**某一时刻的竞价状态**，会随着新申报、撤单窗口内的撤单和价格变化而改变。最后一帧虚拟参考价不是最终成交价的承诺。

集合竞价成交价的确定以交易规则为准。一般原则包括最大成交量、价格优先条件，以及满足条件的价格选择和规则规定的平局处理。不要用一条自己写的简化公式替代交易所撮合规则。

为了描述未匹配量的方向，可以定义：

\[
AI_t=
\frac{U^b_t-U^a_t}{U^b_t+U^a_t},
\]

其中 \(U^b_t\) 为当时未匹配买量，\(U^a_t\) 为当时未匹配卖量。

- \(AI_t>0\)：当时未匹配买量相对较多；
- \(AI_t<0\)：当时未匹配卖量相对较多；
- \(AI_t=0\)：两侧未匹配量相等；
- 分母为 0：该比值**未定义**，不能填成 0。

这个指标只是竞价簿在该时刻的一个横截面描述。它不是最终买卖压力，不代表一定会成交，也不能识别下单者的身份。若数据商没有分别提供买卖未匹配量，不能从一个总量字段反推出两侧差额。

## 4. 逐笔委托、逐笔成交和盘口快照：三种表不是一回事

建议把原始数据分成三个逻辑表，而不是先把所有字段堆成一张宽表。

### 4.1 委托事件表

每条记录描述一条已被数据源发布的委托事件。标准化后的教学字段可以是：

| 字段 | 含义 |
|---|---|
| event_id / sequence_no | 事件唯一键和顺序号 |
| exchange_time | 交易所事件时间 |
| receive_time | 本地系统实际收到数据的时间 |
| security_id / venue | 证券与交易场所 |
| channel_id | 行情通道或序列域（如数据源提供） |
| order_id | 原始委托标识（按接口定义理解） |
| side | 买卖方向 |
| price / quantity | 委托价格和数量 |
| event_type | 新增、撤销、修改或其他事件类型 |

### 4.2 成交事件表

成交事件至少要区分成交本身与订单关联字段：

| 字段 | 含义 |
|---|---|
| trade_id / trade_sequence | 成交唯一键或成交序号 |
| exchange_time / receive_time | 成交时间与本地接收时间 |
| price / quantity / amount | 成交价格、数量和金额 |
| buy_order_id / sell_order_id | 若数据源提供，则为买卖委托关联标识 |
| channel_id | 通道或序列域 |
| aggressor_side | 若提供，必须核对它是交易所字段还是供应商推断字段 |

### 4.3 盘口快照表

快照描述某一时点盘口的状态，例如买卖各 5 档、10 档或产品支持的其他深度。快照不是一条新增委托，也不能单凭相邻两帧差异就知道中间究竟发生了多少次新增、撤单和成交。

**关键原则：** 只有字段字典明确说明订单号的唯一范围、通道语义和成交关联规则，才可以建立委托—成交连接。不能仅凭“时间接近、价格相同、数量相同”去猜测成交属于哪一笔委托。

## 5. 订单生命周期：先做数量守恒，再谈订单流指标

对一笔已被接受、且数据记录完整的限价委托，定义：

- \(Q^{add}\)：原始申报数量；
- \(Q^{cancel}\)：已确认撤销的数量；
- \(Q^{exec}\)：已成交数量；
- \(Q^{open}\)：当前剩余未成交数量。

在没有遗漏、重复、改单歧义和其他特殊状态的简化教学账本中，应满足：

\[
Q^{add}=Q^{cancel}+Q^{exec}+Q^{open}.
\]

这个恒等式是最基础的测量审计。若不成立，应先查明：

- 是否有事件丢失或重复；
- 是否把撤单申请误当成撤单确认；
- 是否把部分成交与整笔撤销混在一起；
- 是否遗漏改单、拒单、废单或订单替换规则；
- 订单号是否只在特定证券、交易日或通道内唯一；
- 数据源是否对成交和撤单做过聚合。

**撤单量不能简单等同于订单消失量。** 订单可能因成交而减少，也可能因撤单而减少；若成交和委托无法可靠关联，真实撤单量就不能被精确识别。

两个经常混淆的比率是：

\[
CancelToSubmit=\frac{Q^{cancel}}{Q^{add}},
\]

\[
CancelShareOfTerminal=
\frac{Q^{cancel}}{Q^{cancel}+Q^{exec}}.
\]

第一个以原始申报量为分母；第二个只比较已撤销和已成交的终结数量。二者回答不同问题，报告时必须写清楚分母。未成交剩余量仍在盘口中，不应该被悄悄放进“已撤销”里。

## 6. 盘口深度、价差与订单流失衡（OFI）

### 6.1 盘口深度失衡

令第 \(k\) 档买量和卖量分别为 \(Q^b_k\)、\(Q^a_k\)，前 \(K\) 档的深度失衡定义为：

\[
OBI_K=
\frac{\sum_{k=1}^{K}Q^b_k-\sum_{k=1}^{K}Q^a_k}
{\sum_{k=1}^{K}Q^b_k+\sum_{k=1}^{K}Q^a_k}.
\]

\(OBI_K\) 位于 \([-1,1]\) 之间（分母大于 0 时）。正值表示所观察档位买量更多，负值表示卖量更多。

必须说明 \(K\) 是 1、5、10 还是其他档位；不同深度的结果不能直接混为同一特征。若两侧总深度均为 0，比值未定义。

### 6.2 买卖价差

\[
Spread_t=P^a_{1,t}-P^b_{1,t},
\]

其中 \(P^a_1\) 是最优卖价，\(P^b_1\) 是最优买价。建议以最小报价单位的整数 tick 保存价格，避免浮点误差；跨证券比较时还要考虑价格尺度和 tick size。

### 6.3 最优档 OFI

Cont、Kukanov 和 Stoikov 的研究从最优买卖报价变化构造 Order Flow Imbalance（OFI）。令 \(P^b_t,Q^b_t\) 为最优买价及其数量，\(P^a_t,Q^a_t\) 为最优卖价及其数量：

\[
e^b_t=
\begin{cases}
Q^b_t,&P^b_t>P^b_{t-1}\\
Q^b_t-Q^b_{t-1},&P^b_t=P^b_{t-1}\\
-Q^b_{t-1},&P^b_t<P^b_{t-1}
\end{cases}
\]

\[
e^a_t=
\begin{cases}
-Q^a_t,&P^a_t>P^a_{t-1}\\
Q^a_t-Q^a_{t-1},&P^a_t=P^a_{t-1}\\
Q^a_{t-1},&P^a_t<P^a_{t-1}
\end{cases}
\]

\[
OFI_t=e^b_t-e^a_t.
\]

OFI 将最优档报价价格与数量变化综合起来，不只是把成交量简单分成主动买和主动卖。它可以由可靠的连续盘口快照计算，但必须保证快照顺序、时间间隔、交易阶段和数据完整性一致。

**迁移限制：** Cont 等人的实证使用美国股票市场数据。公式可以作为微观结构研究的起点，但不能据此断言 A 股的 OFI 有同样的系数、预测力或交易价值。A 股的撮合规则、涨跌停、竞价阶段、行情字段和数据供应方式都需要单独验证。

## 7. 大单、小单、撤单和主动方向：指标名称不等于经济含义

### 大单与小单

可以按照原始委托数量或委托金额分档：

\[
OrderAmount_i=Price_i\times SubmittedQty_i.
\]

阈值必须事前冻结，例如使用研究训练期分位数，或使用预先定义的固定金额区间。不能先看结果再调整“大单”的门槛。

需要同时报告：

- 按原始委托数量分档；
- 按委托金额分档；
- 新增、撤销、成交和剩余数量；
- 买卖两侧各自的分母；
- 阈值是否按价格水平、证券规模和流动性做过调整。

**大单不是机构订单的同义词。** 同一机构可能拆单；个人也可能提交大额订单；一个订单可能被多次部分成交或撤销。没有账户身份数据，就不能把大单净流入直接称为“机构资金流入”。

### 主动买卖方向

如果数据源直接提供主动方向字段，要先确认它的定义和来源。如果是供应商根据成交价与盘口报价推断的主动方向，应标注为“推断方向”，并保留无法判定的记录。不能把供应商推断值伪装成交易所原始字段。

### 撤单率

撤单指标必须建立在可核实的撤单事件和订单生命周期上。只有汇总撤单笔数而没有撤单数量、订单关联和覆盖范围时，只能报告对应的汇总统计，不能声称已经重建每笔订单的完整生命周期。

## 8. 缺失、零值、未定义和不适用：四种状态不能混用

这部分是 L2 研究最容易制造假信号的地方。

| 状态 | 正确解释 | 例子 |
|---|---|---|
| OBSERVED_ZERO | 数据覆盖完整，实际测得为 0 | 完整观测窗口内没有符合阈值的小单 |
| MISSING_SOURCE_COVERAGE | 数据源没有覆盖或数据包缺失 | 某时间段逐笔委托文件缺失 |
| MISSING_FIELD | 记录存在，但计算所需字段为空 | 成交记录没有主动方向字段 |
| UNDEFINED_ZERO_DENOMINATOR | 指标数学上没有定义 | 买卖两侧对应数量之和为 0 |
| NOT_APPLICABLE | 当前数据或交易阶段不适用 | 只有开盘集合竞价快照，没有连续竞价盘口 |

例如，若某时段没有任何可核验的小单事件：

- 完整覆盖、确实没有小单：数量为 0，状态为 OBSERVED_ZERO；
- 小单字段未提供：值为 null，状态为 MISSING_FIELD；
- 供应商漏了一段数据：值为 null，状态为 MISSING_SOURCE_COVERAGE；
- 指标分母为 0：比率为 null，状态为 UNDEFINED_ZERO_DENOMINATOR。

**不要把 null 填成 0，也不要把 0/0 填成 0。** 做分组统计时，未知和未定义样本要单独报告覆盖率，不能悄悄从分母里消失。

## 9. 数据时钟、序列号与 PIT：回测必须使用当时真正收到的数据

一条高频记录至少应区分：

- exchange_time：交易所事件发生或行情标记的时间；
- receive_time：本地采集系统收到消息的时间；
- sequence_no / channel_id：用于按数据源定义恢复顺序；
- available_at：清洗、解码和必要转换完成后，策略实际可以使用数据的时间；
- decision_at：策略做出决策的时间。

对于真实的在线研究，信号可用时间不能早于本地实际接收和处理完成时间。交易所时间相同的记录，要按对应协议的序列规则排序；不能假设所有通道都共享一个全局连续序列号。

最小审计清单：

1. 原始文件不可变保存，记录来源、许可、版本、下载/采集时间和 SHA-256。
2. 检查重复事件、序列号跳号、乱序、补发、断线重连和日内序列重置。
3. 检查证券代码、交易日、通道号和订单号的复合唯一键。
4. 对齐交易阶段，明确集合竞价、连续竞价、停牌、复牌和收盘集合竞价。
5. 分开保存原始字段、供应商加工字段和本地派生特征。
6. 记录每条特征的计算时间，禁止用决策时点之后收到的事件回填信号。
7. 对每个交易日输出数据覆盖率、缺失区间、重复数、未关联成交数和订单生命周期不平衡数。

如果只有分钟级或稀疏快照，无法恢复快照间发生的所有新增、撤单和成交事件。**不要用插值把缺失的逐笔事件“补出来”。**

## 10. 运行教学实验：一份人工 L2 事件账本

本章实验只使用仓库固定的 volume3-l2-synthetic-v1，包括：

- 3 个开盘集合竞价虚拟快照和 1 个最终撮合结果；
- 20 条人工委托/成交事件；
- 11 笔人工委托、4 笔人工成交；
- 6 个人工五档盘口快照；
- 5 个用于区分零值、缺失、未定义和不适用的测量案例。

在项目根目录运行：

~~~bash
python examples/volume3_l2_auction_lab.py
python examples/volume3_l2_auction_lab.py --json
python -m unittest discover -s tests -p "test_volume3_l2_auction_lab.py" -v
~~~

实验完成后，可以检查：

- 买卖两侧的新增、撤销、成交和剩余数量是否守恒；
- 按 400 股的人工门槛区分大单/小单后，各组订单生命周期是否仍能对账；
- 竞价虚拟未匹配量失衡比率如何变化，以及最后一帧虚拟价格与最终开盘价是否一致；
- 最优档和前五档深度失衡是否给出不同描述；
- 最优档 OFI 是否按快照变化正确计算；
- 零值、字段缺失、覆盖缺失、分母为零和不适用是否被分开标记。

这个实验的预期账本是：买方申报 2,450 股，撤销 450 股，成交 1,000 股，剩余 1,000 股；卖方申报 2,300 股，撤销 1,000 股，成交 1,000 股，剩余 300 股。最优档 OFI 的教学序列为 **NA, 0, 100, 150, 300, -150** 股。

**以上数字全部来自人工生成的教学样本。** 它们仅验证代码和数量守恒，不是任何真实股票的统计结果，也不是买卖信号。

## 11. 从测量指标走向研究：先做基线，再谈增量

如果未来要研究 L2 是否有预测价值，建议按以下顺序推进：

1. **冻结数据合同**：交易所、证券范围、数据产品、协议/API 版本、许可、字段字典、采集时间和缺失语义。
2. **先做数据质量审计**：事件覆盖率、序列连续性、订单—成交关联率、订单生命周期守恒、盘口重建一致性。
3. **冻结特征定义**：竞价失衡、最优档/多档深度、OFI、订单新增、撤单和成交结构；每项明确单位、分母、窗口和适用阶段。
4. **设置普通行情基线**：先用 Level-1 可得的价格、成交量、价差和时间特征建立基线，再评估 L2 增量，避免把更复杂的数据误认为天然更有用。
5. **严格时间外验证**：按交易日或更长时间块划分训练、验证和测试；同一天的相邻事件不能被随机拆到训练与测试两侧。
6. **做负对照与稳定性检查**：随机打乱事件顺序、平移信号时间、移除订单关联字段、分阶段/分流动性分层，检查结果是否仍然成立。
7. **最后才进入执行验证**：排队位置、信号延迟、涨跌停、停牌、手续费、冲击和成交概率要在下一章单独处理。

以下任一条件未通过时，应停止策略结论，只保留数据描述：

- 关键字段没有可靠来源或版本；
- 逐笔序列存在无法解释的缺口；
- 订单—成交关联规则不清楚；
- 撤单与成交无法区分；
- 信号使用了本地收到时间之后的数据；
- 大小单阈值、窗口或分母在看过测试结果后才调整；
- L2 特征没有超过普通行情基线，或结果只在少数交易日成立。

## 12. 练习与参考答案

**练习 1：** 09:24:59 的虚拟参考价格和未匹配买量都很高，是否可以直接认定 09:25 一定高开？

**参考答案：** 不能。虚拟值是当时的指示状态，之后还可能有新变化；最终成交价由集合竞价规则和最终申报簿决定。

**练习 2：** 一笔买单从盘口消失，是否说明它被撤销？

**参考答案：** 不能。它可能成交、撤销、被修改或因数据缺失而没有继续显示。需要订单事件、成交关联和数据覆盖审计。

**练习 3：** QMT Tick 中有 bidVol1、askVol1，是否足以计算完整 OFI？

**参考答案：** 只有在字段定义、更新频率、事件顺序、缺失处理和盘口连续性都明确时，才能计算基于这些快照的 OFI。它仍不等同于完整逐笔委托事件流。

**练习 4：** 大单买入金额减去大单卖出金额为正，能否称为机构净流入？

**参考答案：** 不能。大单阈值是研究者定义的分组规则，行情数据通常不提供账户身份。应称为“按该阈值分组的买卖委托/成交金额差”，并说明口径。

**练习 5：** 某分组的交叉成交量为 0，是不是说明这类订单不存在？

**参考答案：** 先核对字段覆盖、分档定义和分母。完整覆盖且确实没有事件才是观测到的零；字段缺失、源数据不完整或分母为零都不能记为零。
